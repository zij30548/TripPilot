# travel_intake

触发：新需求、补充、否定纠正、日期或目的地不明确。

流程：先读当前需求、来源和确认状态；区分本轮修改与未修改字段；保留所有提及城市和真实子问题；缺必要信息或相互矛盾先澄清；逐项展示变更，等待明确确认。

输出：需求字段提议、用户原话依据、仍缺事项和待确认状态。没有修改依据时保留原值；用户建议不等于真实POI或正式草案。

禁止：猜年份、凭空补住宿和景点、悄悄丢弃跨城要求、声称不支持的约束已满足。

程序硬检查：原Selection字段与引文校验、日期及城市范围、当前owner／会话／需求版本。确认前不生成；取消编辑保留原工作。
