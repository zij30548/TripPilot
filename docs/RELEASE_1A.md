## 原因：已确认的诊断缺口与尚未确认的根因

数据链为 `AmapTransitClient.transit → _convert_route/_proposal → ScheduleRouteCollector → build_required_schedule/add_optional_schedule → 前端严格校验 → ScheduleResult`。

| 情况 | 当前判定及依据 | 本轮处理 |
| --- | --- | --- |
| 合法 `transits=[]` | `no_route`，没有参考方案 | 保留，不能解释成数据错误 |
| 必要铁路／轮渡／未知必要方式或没有受支持方案 | `unsupported`，不丢弃必要路段 | 保留，不能说成上游一定坏了 |
| 方案总耗时非法、必需结构或线路／站点缺失、非法非空数值 | `data_error` | 保留拒绝，增加具体固定字段路径及原因码 |
| 未提供几何、票价或单腿耗时 | 合法缺失不等于异常；有效总耗时仍可排程，未知值保留 | 原有行为及回归保持，不归零、不累加单腿时间 |
| 提供了非法／不可绘制的几何 | 现有严格适配器拒绝该候选；如有其他完整有效方案仍按原顺序选择 | 明确记录 `.polyline` 和坐标／不可绘制原因，**未放宽或删除原校验**。是否属于原案例的兼容问题仍需真实响应证明 |
| 已启动路线超时 | `timeout` | 保留，无自动改查步行 |
| 查询额度或共享截止前未启动 | `budget_exhausted` | 保留，不能当作已查询超时或无路线 |
| 上游业务／网络等失败 | `failed` | 保留安全错误，无原始异常、URL 或 Key |

受控样本证明多条校验分支曾经汇聚成同一句错误，因而单凭 `data_error` 无法确定上游无效、适配兼容或绘图问题。这个信息丢失和页面可见性缺口已确认；**并未确认原案例缺少总耗时、必需站点或存在非法几何。**

## 方案与取舍

### 有界、安全的服务端诊断

- `InvalidTransitField` 只携带程序构造的字段路径及固定原因码；不使用上游字段名、数值、原始异常或验证异常的 `input` 作为日志。
- 每次转换失败最多保留、记录 4 个方案首因；路径索引 0～999，超过范围明确记为 `[overflow]`，不误记成第 999 项、不输出上游内容。原因包括 JSON／结构、数值类型／格式／范围、站点文本、坐标格式／范围／非有限及不可绘制。
- `TransitDataError` 仍属于 `AmapError`，单段路线接口安全错误契约不变。采集层将已识别原因映射为安全中文说明，并记录首因与该次 `edge_id`、方向端点 ID；每条失败边另有模式／状态记录，避免并发时无法关联方向。字段诊断最多 4 条、方向首因 1 条、边状态 1 条；连接重试日志沿用原有最多 2 条。
- 不保存完整请求、上游正文、地点名称／坐标、认证头或带 Key URL。新日志是排查线索，不认证客户端地点来源，也不自动认定供应商数据错误。
- 不新增响应字段、存档版本、重试、查询或降级。原选方案策略、分钟向上取整、29/58 上限和共享截止保持。

### 草案顶部显示第一个阻断

正式及复用的草案展示在日期导航之前显示首个未安排必去、原因、必要失败方向、查询时间，以及后续必去未继续／可选未试排之间的关系。保留有效前缀和返程，不把后续地点说成逐个不可行；无前缀时明确没有可验证的必去安排。

前端从已通过契约校验的必去前缀，按现有午餐／时间边界识别当前必要方向；只用于解释，不生成时间轴。Python 实际输出覆盖邻接边、返程、换天及无关失败边，防止把未采用边误报为直接阻断。缺少边记录时明确说缺记录，不推断高德无路线。时间放不下不伪装成路线失败。复用原生成按钮和交通方式设置，无自动请求。

不在缺少原响应时放宽现有几何校验。这保留了原安全边界，也意味着本轮不能保证解决某种尚未证实的有效数据兼容问题。
