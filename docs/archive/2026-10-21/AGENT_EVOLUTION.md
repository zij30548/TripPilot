### 产品体验：一个聊天入口，而不是把旧工作台塞进气泡

- 登录／邀请码注册／退出与用户隔离保留。新默认产品界面拟只保留简洁的会话导航、消息区、输入区和紧凑账号入口，不在首页排列需求表单、地图、天气、费用、媒体和多个AI面板。
- 地点候选、待确认需求、行程结果和修改预览，只在本次对话需要时以消息中的结果卡展示；必要的明确确认不能为了纯文本外观而取消。输入、展开卡片不自行触发外部调用。
- “开放表达”表示用户可以用自然语言提出不同复杂度的旅行需求，**不表示无限制工具、全国全部支持或任意自主操作**。旧六城／七日等约束在对应工具实际扩展前仍适用，不能靠模型聊天放宽。
- 简单请求直接回答或执行一个安全工具；缺信息先问清；确有多步依赖时才进入有界执行。暂不把每条消息都交给多个Agent讨论。
- 照片、视频、地图等旧入口退出新首页。是否重新以聊天附件／结果卡接入，逐项另立范围；媒体旧评分、限额和失败记录不变，知识库生成式问答继续停用。

### 分步交付：每轮有可操作的用户场景

| 顺序 | 用户可见成果与范围 | 依赖／验收与停止点 |
| --- | --- | --- |
| 1. 聊天主入口＋多轮需求澄清 | 保留登录注册；默认首页换成聊天。用户表达旅行需求，系统记住本次已确认信息、澄清缺项并展示需求卡；只有用户确认才发布结构化需求 | 先定义会话／消息／需求版本、本人访问、取消及旧响应隔离；明确刷新恢复边界。不交付固定假回复冒充智能，不声称已经能执行整套旅行任务。首批多轮集覆盖补充、否定、更正、指代、换号与取消 |
| 2. 统一能力目录＋真实只读工具 | 对话中查询真实地点、核对候选及来源。外部读取是只读工具；确认POI是独立用户动作提交需求版本，不由模型自动写入。工具声明输入输出、权限、副作用、版本、额度、超时与错误分类 | 先接少量必要能力，不一次恢复旧面板。直接请求同样受限；跨城、假ID、缺资料不得猜补。每个工具有受控契约测试和另获授权后的真实链路验证 |
| 3. 有界单Agent执行＋确认 | 澄清后调用已登记工具，根据结果选择下一步，生成可核对的行程／修改预览；用户明确采用 | 任务级模型／工具／Token／时间／无进展上限须先冻结；执行与模型选择分开，事实和约束由程序复核。以单步方案为对照；到限、取消、未知结果、错误权限能安全停止，不自动采用或保存 |
| 4. 持久任务与断点恢复 | 用户离开后能看到执行位置、既有结果和待确认项，主动继续 | 新任务／步骤／尝试／审批契约与迁移演练；服务端记录不能只靠前端ref。已发送未知不盲重跑，恢复检查版本和时效；崩溃、并发、响应丢失与额度连续性测试通过后才声称恢复可用 |
| 5. 经同意的长期偏好＋检索质量 | 记住用户明确授权的默认偏好，可查看、修改和删除；检索不足有可定位的改进 | 原话／确认值／模型推断分开。先结构化，再按召回问题评估语义方案；评测召回、选材、条件保真、过期与无资料拒绝，不把检索命中当事实正确。不因此恢复知识库生成式问答 |
| 6. 有真实收益的专业协作 | 确有独立研究任务时做routing，专业子Agent共享需求和任务预算，由协调者提出合并结果 | 与相同工具／数据／预算的单Agent对照，报告质量、延迟、成本及冲突；不能各自提交正式方案。没有真实机票／酒店数据时不虚构研究、库存或价格，更不接交易 |

首轮完成不表示后五轮一并获准。新模型请求的形式、预算和验收额度须在对应实施轮先明确；本次没有授予任何新的真实调用额度。

### MCP、监测与评测如何落地

- **MCP**：能力目录稳定后，再单独选择一个有跨进程复用需求的只读工具实施真实协议适配，验证发现、参数／结果、身份、超时和审计；普通Python函数注册不能宣称是MCP。它不负责替代意图理解、权限或正确性判断，也不是第一轮聊天的前置条件。
- **监测**：从第一轮就记录最少必要的conversation／turn／task／attempt ID、版本、停止原因、工具耗时、结果类别、调用数和可取得的用量。不存思维链、密钥或任意原始网络日志；私有聊天内容与运行日志分开，隔离与保留策略在持久化前明确。
- **故障定位**：区分没理解需求、缺数据、检索没召回、召回但选错、参数／权限错误、上游失败、执行／展示失败。不用一个“Agent失败”或HTTP200掩盖原因。先做确定性指标和告警；若以后增加monitor agent，须证明相对规则监测的额外收益并计入调用预算，不能让它在生产自动改提示或无限重试。
- **效果评测**：使用本项目真实用户场景及脱敏失败建立开发集与冻结集，标明已调试题；每轮预先固定工具、数据和阈值，分别报告任务完成、澄清、约束保持、错误执行、延迟／成本、取消与恢复。模型选择、工具结构合法、业务成功三者分别核对，不编造与业界／benchmark成绩的对齐。
- **改进闭环**：例如检索不足，先核对资料覆盖、中文表达、过滤与排序各环节，再做固定题集对照；不能看见失败就盲目增大top-k、堆上下文或多加一个Agent，并把阅读负担和调用成本藏起来。

当前停止在重构方向和首轮边界明确；不宣称旧UI已替换、新Agent已实现或生产已升级。后续以第1轮的具体契约、页面和多轮闭环开工，保留旧版本的功能、失败与评测含义作为迁移和效果对照。

### 阶段讲解与面试准备：后续每轮固定交付约定

2026-10-20用户补充要求，核对基线`6b460cca0e808aed28731a608ebdd4f45ea95444`。项目要逐步把真实旅行Agent做扎实，**每阶段同时让用户理解自己交付了什么、能解释原理和失败，不仅得到代码或测试总数**。此约定写入AGENTS，供新对话从仓库恢复；不依赖聊天上下文永远保留，不新增功能或模型额度。

每轮报告／PROGRESS至少保留一份可追溯的“阶段讲解卡”，最终回复给简版及文档入口：

1. **状态与业务问题**：阶段ID、提交／代码版本，已实现／离线通过／真实验收／未验收／仅规划分别标注；用一个真实用户需求解释为什么做。
2. **本轮怎么工作**：用户输入→结构化状态→模型／程序决策→工具／数据库→校验→展示；指出模型能决定什么、不能决定什么，不把确定性程序能力包装成模型推理。
3. **改了哪里与为什么这样选**：关键文件、契约和数据模型，复用什么、删除／替换什么；至少说明一个未选方案及其代价。框架／数据库名字不是效果证据。
4. **一个困难或失败**：本轮确实出现的案例、定位证据、原因、补修或保留拒绝；若没有发生，不编造“线上事故”。旧案例只作明确标年的背景，不能冒充本轮新成果。
5. **怎样证明有效**：实际检查命令／结果，受控、回放、真实模型、真实浏览器分别记录；效果分子分母、费用／延迟／未知用量有据才写。旧题调试与冻结题区别、未执行及失败不删除。
6. **怎样使用与演示**：用户可以自己跑的步骤、预期现象、失败时看哪里，安全的本地环境与真实付费入口分开；不把持有服务器权限当作生产认证绕过。
7. **怎么讲与怎么追问**：30～60秒口述稿、需要时3分钟展开，外加3～5个本阶段可能被追问的问题；每题附原理、实际代码／证据和“目前没做什么”。用户应能亲自复现并修改关键路径，辅助编程与自己的需求／决策／评审贡献据实说明。
8. **限制和下一步**：本阶段停止点、仍有的阻塞、下一轮唯一闭环；后续规划不能在简历或口述中提前写成完成。

| 只读工具查询 | [Qwen 工具适配](../../../backend/app/integrations/qwen_tools.py)每次最多一次模型请求、一个原生 tool call；[前端执行器](../../../frontend/src/lib/itinerary-query.ts)读取版本绑定的日期／费用，或展示有限澄清原因 | 没有把工具结果送回模型再决定下一步；**单次工具选择不是 Agent loop**，也没有跨轮指代理解 |
| 解读与调整 | 解读受事实引用约束；自然语言调整只支持一个已安排可选 POI 的排除建议。程序生成预览，用户明确采用；[调整控制器](../../../frontend/src/lib/use-schedule-adjustment.ts)及[草案控制器](../../../frontend/src/lib/use-schedule-preview.ts)同步校验、提交与隔离旧响应 | 模型不能自由改行程；当前前端的原子采用不等于服务端可恢复的任务事务 |
| 业务计算 | 真实 POI 确认、规则排程、时间轴、[整数分费用计算](../../../frontend/src/lib/schedule-costs.ts)、地图与天气边界已有实现 | 预算核对不是预算优化；理解“轻松一点”不等于排程已支持节奏、步行上限、午休或无障碍等新约束 |
| 存档与工作区 | [存档服务](../../../backend/app/saved_trips.py)按身份隔离，保存操作幂等；v3 保存正式快照，v1/v2 保留旧语义。历史副本需主动重生成；当前未保存工作及[冻结保存操作](../../../frontend/src/lib/use-saved-trips.ts)主要在前端内存 | **最终行程存档不是任务恢复、对话记录或长期偏好**；不能从 v3 猜出完整候选、排除历史、待确认预览及工具执行位置，也未实现刷新后恢复不确定保存标识 |
| 工程治理 | release-1D 身份／CSRF／归属、release-1E [持久额度](../../../backend/app/business_usage.py)与[发送边界](../../../backend/app/usage_runtime.py)、请求大小／超时／取消／版本保护，已有冻结评测与脱敏证据 | 额度中的尝试状态不是完整任务检查点；人工验收计数不是生产任务调度器，也不是新模型授权 |
| 注册与协作 | 已有代码内白名单、严格工具 Schema 和专用执行路径 | 尚无统一工具／Skill 生命周期管理、长期记忆、多轮任务服务或专业多 Agent 协作；不因改名就获得这些能力 |

现有六城单选、1～7 天、单住宿、6 必去／3 可选容量不因本路线变化。媒体只提供线索并要求真实 POI 确认；知识库生成式问答继续停用，旧失败、分数、调用台账全部保留。

## 2. 按任务分流，不让简单请求进入复杂循环

| 用户场景 | 拟采用的处理方式 | 停止／确认边界 |
| --- | --- | --- |
| 点按钮查看第二天、查看费用 | 直接调用确定性只读能力，不需要模型；自然语言表达可沿用一次工具选择 | 展示绑定版本的事实、未知项和限制即结束，不追加模型总结 |
| “那天少去一个”，日期或目标不明 | 多轮澄清，保留待填字段；候选从当前有效草案的真实 ID 中产生 | 信息不全不排除、不查新路线；用户取消或目标仍不唯一就暂停，不擅自选择 |
| “先看第二天和费用，再看看不去这个可选地点会怎样” | 仅当动作组合在能力范围内，建立有界步骤，读取结果后决定继续、澄清或生成预览 | 预览不是采用；等待明确确认时结束当前执行，不让后台循环轮询用户 |
| 订机票、自动换酒店、保证不排队，或当前不支持的约束 | 明确说明能力缺口，可澄清可支持的子任务 | 不静默执行一部分，不假装约束已满足；新增领域须另行接入与验收 |

分流依据是动作、缺失信息、依赖与权限，不是句子长短或固定关键词。一次请求若含多个目标，先呈现理解及支持范围；不把解释后的建议直接转成写入授权。复杂任务也应尽量使用确定性步骤，只有需要判断下一步时才消耗模型。

## 3. 分阶段顺序、准入与停止点

以下为**规划序列，不是已批准的开发阶段号**。正式阶段编号、容量、真实样本和调用授权须在各轮开工前细化；没有明确上限的循环不得启用。每阶段沿用第 9 节的共同验收，不以总通过率抵消关键错误。

### 序列 0：现有版本受控上线与演示（当前优先）

- **场景／价值**：邀请用户能可靠登录、规划、核对、调整、保存和历史继续规划。
- **依赖／范围**：release-1F 分步执行与服务器证据；真实 HTTPS／身份隔离、额度、媒体兼容、备份恢复、低内存资源及故障提示。保留现有功能边界，受限能力明确告知。
- **非目标**：不为演示插入新 Agent 框架、会话记忆或多 Agent；本次文档同步不操作服务器。
- **验收／停止**：冻结的主流程、越权、额度耗尽、服务重启、恢复及失败路径均有可核验证据；未验项明确阻止对应开放。完成受控上线验收后单独收口，不自动开始以下序列。

### 序列 1：多轮会话与结构化需求澄清

- **场景／价值**：用户说“就按刚才说的第二天”“就是刚才那个公园”时，系统能提出必要问题，保持上下文而不猜 POI；单独明确的“第二天”查询已经属于现有能力。
- **依赖／范围**：身份隔离、当前草案捕获、明确的会话及需求版本；先复用现有单步工具，区分原话、待确认解析、已确认字段。定义退出、取消、换草案与跨标签页行为。
- **非目标**：不自动排程、不跨旅行记忆、不宣称未持久化的会话可跨重启恢复；聊天记录也不是任务状态。
- **验收／停止**：固定多轮集统计合法指代、澄清正确性、已确认约束保持率和错误执行数；歧义／否定／多目标／ABA／换号均有测试，未经确认的修改为 0。停在会话澄清，不连带开放循环执行。

### 序列 2：工具／Skill 注册与治理

- **场景／价值**：新能力按统一规则接入；用户与维护者可知道某一步会读取什么、调用什么、是否花费或修改状态。
- **依赖／范围**：先登记已有日期查询、费用核对、澄清和排除预览能力，统一 Schema、权限、版本、额度、超时、审计及禁用策略；见第 5 节。
- **非目标**：不做用户上传可执行 Skill、任意代码／URL 执行、插件市场或通用管理后台；不重写排程和费用算法。
- **验收／停止**：注册 ID／版本唯一、未知工具拒绝、权限与参数越界均无副作用；受控超时／取消／额度失败可追踪。旧单步接口及知识问答停用回归。停在可测试的能力目录，不把目录当作 Agent loop。

### 序列 3：有界执行与本次会话闭环

- **场景／价值**：支持先查看安排／费用，再澄清一个目标并生成排除预览的有限组合任务。
- **依赖／范围**：前两序列、工具结果白名单、任务／步骤状态机；允许在必要步骤之间将经过校验的结果交给模型选择下一步。每任务限定模型次数、工具尝试、Token、总截止、重复动作和失败次数，额度覆盖所有子步骤。
- **非目标**：不无限 ReAct、自我修复重试、自动采用／保存、后台无人审批；本阶段暂停仅限仍存在的会话，不承诺刷新或重启续跑。
- **验收／停止**：任务完成、澄清、拒绝和硬约束正确性与单步基线对照；重复无进展、超时、取消、越权、用尽预算均能停止且不超发。停在有界会话内流程，不冒称持久恢复。

### 序列 4：持久任务与安全恢复——首个完整闭环

- **场景／价值**：用户查看预览后离开，回来仍能知道做到哪一步，核对后继续，不重复付费或重复采用。
- **依赖／范围**：任务、步骤、尝试及审批检查点；服务端持久工作副本的明确契约、身份归属、版本并发控制、恢复前校验。实现第 6 节有限闭环与第 7 节恢复语义，不借用 v3 存档充当任务库。
- **非目标**：不追认旧浏览器内存为可恢复任务，不保证任意外部服务 exactly-once，不自动刷新所有过期资料或返还不确定尝试额度。
- **验收／停止**：在发送前、发送后、结果持久化前后、采用／保存提交前后分别注入故障；重启／双标签竞争／旧确认／不确定调用均不得产生未经授权的新尝试或重复提交。正常恢复链路完整，故障链路安全暂停；停在一个可选地点的闭环，不扩成任意改行程。

### 序列 5：长期偏好与可执行旅行约束

- **场景／价值**：经用户同意保留偏好，下次减少重复输入；区分“喜欢轻松”与本次明确的可执行限制。
- **依赖／范围**：前述版本与恢复机制、偏好来源／范围／有效期／修改删除；新约束必须有数据、算法表示及违反检测。先做用户确认的结构化偏好，不先堆对话向量库。
- **非目标**：不把模型猜测、敏感推断或一次旅行条件自动永久记忆；不以“已理解”冒充排程已满足步行上限、预算、预约或无障碍需求。
- **验收／停止**：本次明确要求覆盖默认偏好，冲突显式澄清；跨账号泄漏为 0，编辑／删除／过期后不再应用旧版本。逐类约束用可行／不可行样本验证；仅开放通过的约束，未支持的保留为未执行事项。

### 序列 6：有真实业务依据的专业协作

- **场景／价值**：交通和住宿确有独立研究、比较与条件核对任务时，专业子 Agent 并行提出候选，由协调者合并。
- **依赖／范围**：真实机票／酒店数据接入条件、任务恢复、工具权限及共享预算、领域输出契约和确定性校验；详见第 8 节。先研究／比较，不预订支付。
- **非目标**：不因“旅行有多个模块”就每模块建一个 Agent，不让子 Agent 各自提交行程，不把普通预算计算改为模型算术；预订／支付为以后独立授权阶段。
- **验收／停止**：相同工具、数据与权限下和单 Agent／确定性工作流比较，记录任务质量、关键错误、耗时、调用成本与冲突恢复；仅在预先约定的业务收益达到门槛且安全回归通过后接入。无收益或无真实数据则保留模块化单流程，停在比较结论，不强行为引入框架而上线。

产品能力扩展（更多城市／容量、媒体、多住宿）仍见 [ROADMAP](../../ROADMAP.md)；上述技术序列不自动改变其范围。排程优化保留，按真实用户收益另立题集和约束，不成为上线演示或第一闭环的前置工程。

## 4. 状态职责、版本与前后端持久化边界

以下是**拟建概念模型**，不是当前 API、数据库表或已实现自动保存：

| 对象 | 负责什么／不负责什么 | 关联与版本要求 |
| --- | --- | --- |
| 会话 Conversation | 用户原话、澄清轮次、可追溯的解析结果；不是事实数据库或自动授权凭证 | 服务端身份、独立 conversation ID／revision；更换账号不可继承，对话裁剪不能丢失确认来源 |
| 结构化需求 Requirements | 已确认的本次目的地、日期、地点 ID／顺序、设置及已支持约束；原话与待确认解析分开 | revision 单调递增；同时保留字段来源、确认记录，模型推断不直接发布成正式需求 |
| 工作副本／正式草案 | 用户正在规划的需求、设置、候选与排除、正式结果及相关费用；未采用预览不是正式结果 | 独立工作区会话身份，需求、候选、草案、费用等依赖版本明确；不能只用内容相等或 generated_at 识别版本 |
| 任务 Task | 一次受支持的目标、依赖、执行计划、总预算、状态、停止原因和待确认点 | owner、task ID／revision，绑定输入版本和能力版本；会话可有多个任务，不把整个聊天当一个永不结束的任务 |
| 步骤 Step | 一次确定性动作、必要模型选择或等待用户；保存完成条件与校验结果 | task＋step ID、依赖步骤、输入／结果引用；完成不代表整任务成功，暂停不保持占用工作线程 |
| 工具尝试 ToolAttempt | 一次实际发送／执行的意图、状态、结果摘要、用量或未知，以及错误阶段 | 独立 attempt／operation ID，关联任务、步骤和现有额度尝试；逻辑步骤与物理重试分开计数 |
| 调整预览 Preview | 冻结原方案、拟输入、目标可选 ID、新路线结果与差异；不是批准记录 | base draft／候选／规则版本、preview ID／revision，采用需精确绑定所见预览及当前身份，不以一句孤立“好”确认任意待办 |
| 长期偏好 Preference | 用户同意跨旅行保留的结构化默认值、来源、适用范围、有效期、撤回状态 | owner、preference ID／revision；任务记录使用哪一版，偏好更新不偷偷改当前已确认需求 |

当前 Hook/ref、AbortController、Object URL、地图对象、登录 Cookie、原始媒体等**不直接序列化**。将来持久化必须用白名单契约，区分浏览器展示状态与服务端业务状态；密钥、原始媒体、任意完整网络日志不进入任务检查点。任务存储与最终 v1/v2/v3 快照分别版本化，兼容方案另行设计，不能放宽旧存档校验或回写旧记录。

迁移路径应先明确输入和权限，再引入可恢复工作副本：浏览器仍可进行临时编辑，只有用户确认后才发布新的结构化需求；服务端持久任务读取已验证版本，不能凭客户端自报 owner 或模型字符串执行。当前客户端 draft_version 只是请求绑定值，不是已有的服务端权威工作区版本；未来接收草案、候选和费用时须重新校验白名单内容，登记服务端版本与来源。费用工具仍复用现有计算语义，不因持久化另写一套金额规则；内部一致校验也不认证上游真实性。

后续服务端采用入口先检查 expected revision、审批目标和完整结果，再原子提交正式状态与操作收据；当前前端同步采用不能原样当作跨进程持久保证。多轮确认后仍要通过现有明确排除意图、可选身份和硬约束校验，不能由聊天摘要绕过授权。保存继续复用现有 `(owner_id, operation_id)` 幂等语义；要跨刷新安全恢复，须在执行前可靠保存操作标识及冻结内容引用，不能仅依赖现有内存Hook，更不能恢复时另造 ID 重复建档。

所有异步提交再次核对会话／任务／依赖版本，A→B→A 也不能复活旧回调。依赖按能力声明：费用变化使相关费用结果过期，但**不因此清除正式草案、把预算变成采用门槛，或自动作废不依赖费用结论的排除预览**；天气变化只影响依赖该天气依据的步骤。草案／候选／规则变化使相关旧预览失效。展示日期、地图选择不应充当业务版本。

## 5. 工具与 Skill 注册约定

这里的 Skill 指产品内经过审查的能力组合／操作规程，不是仓库 `AGENTS.md`、Codex 技能或能自行获得权限的提示文本。工具执行一个有类型的操作；Skill 可以声明如何组合工具、何时澄清和停止，但不能绕过执行器。

每个注册项至少声明：

- **身份与契约**：稳定 ID、语义版本、用途、严格输入／输出 Schema、字段和集合上限、错误码、真实实体引用、所需数据来源及新鲜度。拒绝额外字段与未知能力；返回结构合法仍须检查业务前提。
- **权限与副作用**：只读本地、外部查询／计费、生成预览、正式采用、持久保存分别标记；服务端逐次鉴权与归属校验，不接受模型扩权。生成预览也会消耗路线额度，不能当作无成本读取。
- **预算与执行**：任务级模型／工具／Token／总时长上限，兼容现有账号／全局服务额度和单请求路线上限；每次物理发送及原有连接重试分别计数。子能力、子 Agent 不获得新预算；不新加隐藏重试层。
- **生命周期**：超时、取消传播、可否安全重试、幂等键、发送不确定状态、结果有效期和审批要求。到限、无进展重复动作、缺数据、版本漂移、权限撤销、用户取消或等待确认均明确结束／暂停。
- **治理与验收**：责任模块、版本变更及退役说明、测试样本、业务成功／拒绝标准、脱敏追踪字段。旧任务遇到能力版本不兼容时停止并说明，不能静默升级后继续执行。

注册清单只提供已授权能力；用户或检索／图中文字不能动态注册工具、生成可执行代码、指定任意 URL 或导入依赖。模型输出不得直接提交正式行程。采用／保存需要专门的用户确认事件；循环只能提出待确认动作，不能用自身的下一轮输出替代用户同意。

## 6. 首个完整闭环的限定用户路径

该闭环在序列 4 才承诺跨刷新／重启继续；此前对应能力不是已经实现的多轮流程。

1. 捕获用户当前有效正式草案与费用版本；按需查询指定日期安排、核对全程费用。时间、地点、未知／非法费用由程序读取／计算，不让模型补事实。
2. 用户提出一个可选地点调整；有歧义时多轮确认其 POI ID 和本次意图。仅允许当前已安排的一个可选地点，不能通过会话把必去变可选或暗中扩展到多个修改。
3. 用户明确请求预览后，复用现有排除输入构造、排程与严格校验，正式草案和候选排除集合不变。新候选可能进入前三，不称为自动室内替代或保证更省钱。
4. 保存任务的待确认检查点并暂停，显示来源版本、所见预览和尚未采用；不持续占用模型调用或后台轮询。用户回来后主动继续，按第 7 节核对时效和当前版本。
5. 有效时让用户查看差异并明确采用；已过期则保留历史说明，要求重新确认是否重新查询，不盲用旧结果。沿用全部必去安排、至少一个 visit、返程等采用校验；未知／非法费用不新增采用门槛。
6. 通过唯一协调提交路径同步更新候选排除、匹配设置、正式结果及绘图附件，失效旧解读／关联检查，保留同 ID 合法用户输入。另存仍是独立主动操作，不自动创建最终行程存档或覆盖旧记录；任务检查点持久化与最终存档是两种不同职责。

首闭环不新增交通策略、营业／预约验证、预算优化、天气自动调整、地点替换算法或真实机票酒店查询。取消保持原正式方案；外部输入已经被用户改动时，不用取消去恢复覆盖这些新输入。

## 7. 暂停与恢复不是重新执行整段代码

恢复先验证身份、权限、任务／工具版本、草案及相关输入版本、数据来源和查询时间，再决定继续、重新澄清或等待显式重新查询。旧数据不能因为恢复或重新渲染而刷新时间；“仍可展示”与“仍可据此采取行动”分开判定，各来源的有效性规则另行定义。

| 检查点状态 | 允许的恢复行为 | 禁止行为 |
| --- | --- | --- |
| 尚未发送、没有不确定的预记尝试 | 重新核对输入、权限和剩余额度后，按已确认任务及恢复动作继续 | 当作历史授权自动开启新的付费循环；超出总预算 |
| 已预记／已发送，结果未知 | 保留尝试和额度占用；若服务支持安全按操作 ID 查询，可走单独受控核对，否则标不确定、等待处理 | 认为超时＝没执行，换 ID／重启／换子 Agent 盲重发或返额 |
| 结果已可靠保存且仍有效 | 复用已校验结果，从下一未完成步骤继续，记录本次恢复 | 为重建界面再调用同一外部服务 |
| 资料陈旧、草案或相关约束变了 | 旧结果只读展示，失效依赖步骤与审批；说明需要用户重新确认的动作及可能新费用 | 自动刷新所有来源，或把旧预览强行采用到新草案 |
| 采用／保存可能已提交，响应丢失 | 以同身份、同操作标识与内容查收据／幂等重试；版本冲突停止 | 再次采用、另建保存 ID，或声称网络取消必然回滚 |
| 账号退出、撤销或换号 | 清理浏览器旧状态；恢复需重新鉴权并核对 owner，旧任务只能由有权身份查看 | 依赖浏览器已有 task ID 绕过归属，恢复后串账号 |

持久化前后故障窗口、同任务并发认领及“确认已提交但界面未收到”的情况须有可测试状态；实现方式在该阶段选择。**外部 API 不支持幂等时不能承诺全链路 exactly-once**。新尝试必须符合明确的重试策略、用户确认和额度，不把 loop 自主继续当作无限授权。

## 8. 长期偏好、旅行约束与专业协作

### 8.1 原始需求、确认偏好与模型推断分开

- 原始需求：记录用户本次实际表达及上下文，含否定和不确定性；解析可以失败，不直接当可执行参数。
- 已确认偏好：用户明确同意保留的结构化默认值，注明来源、确认时间、适用范围、有效期和可编辑／删除状态。一次同行人数或本次日期不自动变成长期偏好；不从照片、同行人或聊天推断健康等敏感属性并永久保存。
- 模型推断：只是待核假设，不自动成为硬约束、长久记忆或正式需求。需要应用时先解释并确认；用户拒绝后不借摘要重新引入。

适用顺序：安全与系统能力边界 → 本次明确确认的旅行要求 → 适用且经确认的默认偏好；冲突需提示而不是静默丢约束。新记忆版本不偷偷改变正在执行的任务。偏好存储、会话／追踪保留期、撤回与删除必须按账号隔离并另行设计，不等于现有存档已提供这些能力。

例如“少走路”可先作为待量化偏好；只有步行距离来源、约束表达、排程支持和违反检测都完成后，才可声称执行“每日不超过某距离”。已有费用核对仍不自动保证总预算，住宿参考点不等于可订房间或价格，现有公交参考不保证出发时刻班次。

### 8.2 协调者＋专业子 Agent＋确定性校验

多个业务领域首先需要清晰模块；只有存在独立的信息搜集、比较与判断步骤，并且单流程对照证明收益，才拆成专业 Agent：

- **协调者**：澄清目标、发布只读需求版本、拆分任务、分配共享预算、收集冲突和停止理由；只能提出合并预览，不能替用户确认。
- **专业子 Agent**：例如未来交通／住宿研究，根据同一需求版本输出有来源、查询时间、适用条件及未知项的候选；权限与预算限于分配范围。不能各自更改需求、排除地点、采用或保存正式草案。
- **确定性校验与唯一提交入口**：检查城市／日期／人员／金额／约束、引用和来源、必要交通／住宿连续性；预算由程序计算，不能靠 Agent 互相表示同意。检查可证明内部一致性，不能把供应商数据认证成保证可预订。

子任务共享父任务额度和截止时间；并行预留也必须原子计数，不能每个 Agent 各获完整预算。结果绑定需求／候选版本，过期响应丢弃；冲突返回具体字段和依据，限次修订或请求用户决定，不无限讨论。用户修改要求后，受影响子结果失效，协调者不能拼接不同版本的“最佳答案”。

**机票、酒店先过真实数据接入门槛**：明确供应商／许可与地域、账号权限、查询字段与费用、实时性、余量、税费、退改／入住／人群条件、报价失效、调用上限及脱敏要求；高德酒店 POI 和静态知识不提供房价、库存或机票能力。数据缺失时只说明无法研究，不用模型记忆补价。

研究／比较通过后才考虑独立的预订／支付阶段；后者另需订单与支付安全、实时复核、明确金额与条款授权、幂等和不确定订单核对、退款取消及人工介入。**本路线不授权接入交易、代订或扣款**，也不把多 Agent 作为跨城／媒体功能的必需前置。

## 9. 评测、追踪与后端治理贯穿每阶段

以现有单步方案为基线：相同工具、数据、权限、问题和预算下对照；原先不支持的多步任务另列，不通过修改旧标签夸大提升。固定开发集、冻结验证集和故障场景，保留全部失败／未执行；已调试题不冒称盲测。真实调用须另获明确额度，历史台账不能续用；受控测试、离线回放与真实端到端分别报告。

共同指标与准入：

1. **效果**：合法子目标覆盖、澄清准确性、工具／参数选择、硬约束保持、错误事实／无依据承诺、未知项呈现、用户确认是否匹配所见方案；给实际分子／分母与具体失败。不得以总成功率抵消越权、错误采用、身份泄漏或重复付费等阻塞。
2. **效率与费用**：完成一次任务的模型／工具／物理发送次数、Token（缺失记未知）、延迟分布、暂停次数、重复无进展步骤；次数限额不冒称人民币精确上限。阶段开工前冻结可接受成本与延迟阈值，不看完输出再调门槛。
3. **恢复与一致性**：ABA、晚 success/error/finally、双标签／并发、撤销身份、过期数据、工具版本变化、发送结果不明、提交响应丢失、重启和恢复后的额度连续性；无授权新发送、重复正式提交及跨账号污染为 0。
4. **可追溯**：会话／需求／任务／步骤／尝试／预览 ID、版本／契约／提示哈希、来源时间、实际模型标识（未知不造）、校验结论、限额与错误阶段，能区分模型选错、数据不足、执行失败和用户取消。最少必要内容、账号隔离和保留期先明确，不默认存完整提示、私人行程／图片、认证头或思维链。
5. **工程治理**：严格接口、统一受控错误、每次执行前鉴权、原子额度、取消与资源回收、能力禁用、可诊断故障、备份与恢复演练；沿用现有边界，不能靠界面按钮代替后端校验。实际吞吐和故障证据决定部署及存储调整。

Skill、loop 和多 Agent 都须报告比基线改善了什么、增加了什么成本、仍有什么失败；未通过就停在报告或受限入口，不边运行边扩大权限、换题或追加额度。知识库生成式问答质量未准入的结论不因本路线改变，旧失败和评分不重算。

## 10. 技术选型由问题触发，不以框架名称交付

| 候选 | 何时值得评估 | 不可替代的责任／当前选择 |
| --- | --- | --- |
| 自有状态机／LangGraph 等编排 | 有界步骤、分支、检查点、审批和恢复复杂度已有实际证据时，比较实现与维护成本 | 当前未引入；图编排不能自动提供权限、业务校验、幂等或安全恢复，不为获得框架标签重写已有流程 |
| SQLite／PostgreSQL | 任务持久化阶段先评估现有 SQLite 的事务、锁、备份和单机部署约束；多主机或写入并发确实不足时再评估 PostgreSQL | 本轮不改库；未来新状态须独立版本／迁移／回退／兼容验证，不重建用户库或返还历史额度 |
| Redis | 多实例共享短窗口、协调或队列出现具体需求时评估，连同部署、故障与一致性成本 | 不把易失计数当持久硬额度，不把队列消息当唯一任务真相；不是上线或 loop 的必需依赖 |
| 向量库／语义检索 | 结构化字段不足，且大量授权记忆／资料检索有可度量的召回问题时做对照 | 先使用可解释的结构化偏好；检索相似不代表当前有效、用户确认或正确答案，不借此恢复知识问答 |
| 工具协议／外部连接层 | 真正存在跨服务复用、版本协商、鉴权隔离与可审计来源需求时单独评估 | 不因“Skill”一词接入任意第三方工具，不绕过固定服务地址、代理和模型配置边界 |
