# 高德 MCP 地点搜索接入：第一步

2026-10-24；基线 `main / e35e59df1972b70457a3c4f9dd8eb19e77186e17`。用户明确要求接入上一轮讨论的高德MCP。本轮只实现**聊天地点准备中的只读关键词搜索**，不接路线／天气MCP、不恢复知识库生成问答、不修改模型／提示／存档，不切换现有服务或云端。

**当前结论：代码接线与受控标准协议验证完成，真实高德MCP尚未验收。模型、高德及其他业务外部API调用均0。默认仍REST，没有偷偷更改本机配置或网站。** 之前旅行真实验收3/21失败／余18暂停独立保留，不是本轮额度。

## 1. 它在产品里用在哪里

用户主动搜索真实地点 → 原聊天地点API核对工作区／版本 → 服务端选择REST或MCP → 返回候选 → 用户预览地址 → 明确确认住宿／必去。

MCP模式内部使用真实标准协议：`initialize → notifications/initialized → tools/list → tools/call(maps_text_search)`，不是把普通JSON意图选择改名叫MCP。千问仍选择现有业务动作，远端工具描述和Schema不会直接注入模型提示；选地点、采用行程与保存权仍属于用户。只打开页面、切城市、预览和确认已有候选不会建立MCP会话或自动搜索。

两条接入路径共用[客户端工厂](../backend/tooling/providers/chat_places_factory.py)：

- [聊天地点API](../backend/api/chat_places.py)：实际`/chat/conversations/{id}/places`操作。
- [兼容助手搜索分支](../backend/api/assistant.py)：保留旧调用和当前严格确认规则。

正式排程、候选聚合、天气、地图代理和照片模型不改用MCP。全国城市目录仍不等于全国排程／资料问答开放。

## 2. 复用了什么，为什么还要适配

原上传EchoMind确有标准MCP客户端，默认远端为微软文档，并不是高德。本轮保留[原客户端](../backend/echomind_core/upstream/tooling/mcp_client.py)及`SOURCE.json`不变，复用其配置／工具别名／目录注册／原生调用和关闭机制，使用已锁定的官方MCP SDK **1.26.0**。

新增[有限生命周期适配](../backend/tooling/providers/amap_mcp.py)替换原客户端自动重连／动态刷新循环；远端白名单仅`maps_text_search`。工具的只读权限由本地固定白名单决定，不将远端`readOnlyHint`当安全证明；缺提示不伪造元数据，明确破坏性或非只读声明则拒绝。远端Schema还须匹配本地调用所需的`keywords/city/citylimit`字段。当前是受控实现，真实目录是否完全兼容尚待验证。

原客户端的`bounded_result`可能裁剪内容，本适配在其之前验证完整原始结果，且**只接受`truncated=false`**。裁剪、缺字段、资源引用、自由文字、多个竞争结果、文本／结构化JSON类型矛盾均失败；不会删掉非法字段、截第一条或把不完整列表称为完整候选。

固定官方地址及Streamable HTTP选择依据为[高德官方接入说明](https://developer.amap.com/api/mcp-server/gettingstarted)，本轮只读取公开文档，没有向带Key的MCP地址发送探测。SDK源码也已核对；旧SSE连接方式不作为当前接入配置。

## 3. 安全、额度与资源边界

| 项目 | 当前实现与限制 |
| --- | --- |
| 上游与密钥 | 固定HTTPS `mcp.amap.com/mcp`；仅服务端拼接一项Key查询参数，32位十六进制；无可配置任意URL、重定向、环境代理或浏览器密钥 |
| 请求／响应 | 单RPC请求≤8KiB，单响应解压后≤256KiB；JSON拒绝重复键／非有限数。有限完整POST-SSE可读，续传ID／重试／不完整流拒绝 |
| 目录／Schema | 单页最多32工具、目录≤64KiB、Schema≤8KiB／深度12；重名、分页、外部引用、任意正则及高成本唯一性校验拒绝。只注册允许的搜索工具 |
| 结果与POI | 结果≤96KiB，最多20候选，保留原完整性／ID去重；仍复用[原`normalize_places`](../backend/tooling/providers/chat_places.py)，必须有真实返回的坐标、citycode／cityname／adcode并一致 |
| 网络次数 | 每次操作最多4个POST：3个协议控制＋1个业务工具调用；不重连、不刷新目录、不重试或自动切REST。SDK隐式GET仅在本地拒绝405，不发送网络；不发送关闭DELETE |
| 持久额度 | 实际`tools/call`发送前走原持久`amap_poi`取额／dispatching；失败、已发取消及不确定不返额。协议控制不计为POI查询，但有请求／时间／并发边界 |
| 额度单位 | MCP侧的一次工具发送，不证明供应商内部只尝试一次REST，也不是精确人民币账单。官方内部调用、网络与服务成本尚待实测核对，不拿浏览器请求数冒充上游尝试数 |
| 时间／容量 | 初始化＋发现＋调用共享20秒；进程最多3个搜索会话，满时拒绝而不无限排队。原客户端清理到10秒会取消并继续等待排空，清理时间与处理截止分开，不承诺上游停止计费 |
| 身份与生命周期 | 请求内建会话，绑定当前服务端owner／请求路径／额度存储；避免后台任务继承错误用户。实际工具取额前、取额后发送前再次核对当前操作版本；兼容助手同时核对地点副本而非只比聊天版本。保留原CSRF、取消、CAS、操作幂等和明确确认；清理完成才释放容量 |
| 日志 | 现有HTTP密钥脱敏；精确隔离SDK可能输出RPC／会话ID的logger，包括其通用`client`名称。SDK日志名跨连接共享，原始SDK诊断会一起被抑制，不影响应用日志／执行；不保存Key、原始工具正文或私人查询 |

这些限制位于[传输边界](../backend/tooling/providers/amap_mcp_transport.py)，不是仅靠按钮或提示。SDK后台异常可能延迟到RPC超时，适配通过请求局部失败事件及时取消／排空等待，保留原`UsageError`及429，不把限额错误变成空结果或成功。

**城市归属不能从搜索参数补造。** 即使关键词、请求城市正确，上游若缺城市字段、跨城或坐标异常，仍整批拒绝。不自动发详情查询、不逐个补查REST；真实官方MCP若只返回精简POI，本轮实现可能正确拒绝，必须另有明确方案和预算后再适配，不能放宽现有确认标准。

## 4. 如何配置（本轮没有替用户填写或重启）

默认安装／服务行为不变。需要启用时，先在预定独立环境核对依赖与配置；不要对当前正在运行的venv直接同步以免中途替换依赖。

```sh
cd /Users/zijing/projects/trippilot/backend
uv sync --frozen --extra amap-mcp
```

最小选装组仅增加已经锁定的`mcp==1.26.0`与`jsonschema==4.26.0`，不要求Redis／Chroma、额外模型或新服务。普通REST启动不导入MCP；显式选择MCP但缺依赖时只有该搜索明确失败，不静默回退。

手动编辑后端 `/Users/zijing/projects/trippilot/backend/.env`，保留已有变量，按[示例](../backend/.env.example)填写：

```dotenv
CHAT_PLACES_TRANSPORT=amap_mcp
AMAP_MCP_KEY=自行填写高德官方对应权限的Key
```

此处是说明，不是可直接复制的真实凭据；不要把Key发到聊天或前端。REST仍使用独立`AMAP_WEB_KEY`，MCP不会擅自拿它当后备；不需要修改千问配置。固定地址不需要另填URL。改回`CHAT_PLACES_TRANSPORT=rest`只选择旧链路，不清库／返额。实际切换须按当前服务与数据库版本另行审查，本轮没有启动／重启服务、部署云端或扩充生产配置白名单。

## 6. 验收边界、后续与面试

本轮停止在**可显式启用的MCP搜索接线与离线验证**。真实高德MCP的权限、目录版本、返回字段、网络／延迟和账单未验证；未切当前3110／8804／8000或线上。知识问答继续停用；旧真实3/21和18暂停不动，旧成绩、样本和台账不重算。没有新增模型调用授权。

下一步只建议另行固定小型真实MCP搜索计划：一次正常地点、一次无结果／字段边界，再核对程序候选与确认、实际计数和密钥脱敏；不需为了连通性调用千问。本轮不执行，不能把未来计划当已获调用额度。之后才按证据考虑天气或路线MCP，不同时替换所有高德链路。

面试口述：模型的function calling决定选哪个业务工具，MCP负责标准化发现与调用外部工具，高德提供真实数据。我们复用原框架客户端，但把连接、白名单、身份、版本、持久额度和取消放在程序边界；MCP不是绕过业务校验的捷径。受控测试验证标准协议和状态，不证明真实高德返回足以确认POI，更不证明任何旅游问题都会答对。

- 为什么不是把HTTP函数改名？真实SDK完成initialize／发现／tools/call，线上协议与内部业务契约分开，测试检查实际RPC序列。
- 为什么不直接启动原客户端？它的自动重连、动态目录、日志和裁剪不适合当前有界旅行操作；原文件仍保真，适配层负责限制。
- 为什么保留REST？它是明确配置的对照链路，不是失败后双发；新接入未真实验收不能无声替换。
- 为什么查了上海仍检查城市？参数是查询条件，返回的归属才是当前证据；不能把客户端／模型意图当认证。
- 为什么一次MCP调用不等于一笔确定费用？供应商内部尝试和计费不可从协议次数推出；程序保证自己不超发、不随意返额，不编造账单。
