chat-1已实现多轮需求意向及持久化，离线／受控流程通过；真实模型语义验收、新聊天生产备份／恢复及线上MySQL切换仍未完成。当前不自动开始chat-2，实际检查见 [CHAT_1](CHAT_1.md)，最新停止点见 [PROGRESS](PROGRESS.md)。

聊天意向中的地点文字不是已核实Place，用户确认意向也不等于可生成行程。六城、1～7天、单住宿、6必去／本次3可选仍是旧旅行工具当前边界，不是永久产品限制；成都公交等历史限制保留。知识库生成式问答继续停用。

## 按任务分流，不按句子长短增加复杂度

- 简单操作：确定性只读工具直接执行；自然语言可用一次工具选择，不追加无必要总结或loop。
- 信息缺失：先澄清日期、目标或不支持的约束；未唯一确认，不查路线、不执行修改。
- 多步任务：仅受支持组合才进入有界执行；模型／工具／Token／墙钟／无进展均设上限，等待确认、取消、到限或版本漂移即停。
- 不支持的部分必须明确说明，不能静默执行剩余部分，也不能因“理解了偏好”宣称排程已经满足。

单次工具选择不等于Agent loop；会话持久化、最终行程存档和额度收据也分别不等于长期偏好或完整任务恢复。

## 数据职责与唯一权威状态

| 层次 | 职责与版本边界 |
| --- | --- |
| 会话／意向 | chat-1保存用户原话、结构化提议、来源与显式确认；账号、conversation、operation和revision绑定，推断不能自动变成确认 |
| 真实POI／旅行需求 | 未来由真实搜索及用户确认产生ID、坐标、归属和顺序；不能直接采纳模型地点文字 |
| 工作副本／正式草案 | 旧规划主要仍在前端；未来接入聊天工具前须建立服务端权威版本，区分输入、正式结果及未采用预览 |
| 任务／步骤／尝试 | 尚未实现完整执行器；未来分别保存目标、依赖、停止原因和物理发送状态，不把整个会话当永不结束的任务 |
| 预览／确认／存档 | 预览冻结原方案与依赖版本；采用须确认所见结果，保存沿用归属及操作幂等，不改旧v1/v2/v3语义 |
| 长期偏好 | 尚未实现；用户明确同意后才跨旅行复用，保留来源、范围、有效期和撤回能力，本次要求优先于默认值 |

前端Hook、地图、Object URL、媒体、Cookie及任意React状态不得整份序列化。新的持久工作副本／任务另定白名单契约、显式迁移与恢复，不自动建表或切生产库。
费用保持单一计算规则：未知不当零、参考小计不当完整总额；不能前后端另写两套。依赖按能力声明：费用变化失效相关费用结果，不自动清草案或增加采用门槛；天气只失效依赖它的依据，地图展示不充当业务版本。
每次提交重查账号、操作和依赖版本；ABA、旧success/error/finally不得恢复状态。恢复先查时效及版本，已发送未知不盲重跑或返额，保存响应丢失复用原操作与冻结内容；外部API不支持幂等时不承诺exactly-once。

## 能力、执行与协作的准入

- 工具／Skill注册声明严格输入输出、版本、权限、副作用、真实来源／时效、额度、超时、取消、幂等、错误及停止条件；Skill不能自行扩权或动态执行模型代码。
- 先有真实旅行确定性闭环和单步对照，再引入工具结果反馈的有界loop，随后补任务暂停／恢复与经同意的偏好；具体chat-1～chat-9只在阶段计划维护。
- 首个拟建完整闭环限定：查询某日安排、核对费用、多轮确认一个可选地点、生成排除预览、暂停后继续、明确采用；当前chat-1尚不具备该执行闭环。
- MCP须有真实跨服务协议与鉴权验收；monitor先用确定性指标／脱敏追踪，另加模型监测须证明收益并计入预算。注册函数、框架名或另开一个Agent都不是交付质量证明。
- 多Agent仅在独立研究任务及同工具／数据／预算对照证明收益后采用：协调者分配共享需求版本、父任务预算和截止，专业子Agent只交候选，确定性校验后由唯一入口提交，不能各自改正式草案。
- 机票／酒店先核对真实数据许可、价格／库存时效和人群条件；研究比较与预订支付分阶段，住宿POI不等于报价或库存，不授权交易。
- LangGraph、Redis、向量库等按具体问题另行选型；当前可显式使用MySQL、保留SQLite兼容，不为技术标签自动迁库或重写旧实现。

## 阶段讲解与面试准备：后续每轮固定交付约定

每阶段用真实代码和证据说明：用户问题与状态 → 输入／模型／程序／工具／数据库数据流 → 关键改动与选型取舍 → 实际失败／限制 → 检查与复现 → 停止点。已实现、离线验证、真实验证、规划和未验证必须分开。
最终回复提供简版、30～60秒口述和3～5个项目追问；专项报告给有代码依据的答题提示，让用户能亲自运行及修改关键路径，不只背测试总数或虚构经历。
常见追问围绕：意向与真实地点如何区分、Schema为何不证明语义正确、版本如何阻断晚响应、未知调用为何不能重发、何时多Agent确有收益。每轮结合实际改动回答，不假定未来能力已经完成。
评测同时核对过程与最终业务状态、合法问题覆盖、约束、来源、成本、取消及恢复；保留失败和分母，受控／回放／真实证据分开。重要越权、错误采用、重复付费或数据丢失不能被总通过率抵消。
每阶段按Harness交付卡审视全部12维，写清已验证、待验、缺口或有理由的不适用；没有实现统一trace／CI／恢复就如实记录。历史模型额度不能续用，不自动追加调用或用提示代替程序约束。
