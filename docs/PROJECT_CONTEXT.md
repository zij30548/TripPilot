# TripPilot 产品与架构上下文

更新：2026-10-21。本文件只维护当前事实和长期定位；实际交付、失败与停止点见[PROGRESS](PROGRESS.md)，旧交付记录见[历史导航](archive/README.md)。历史报告中的“当前”只表示其当时状态。

## 产品定位与长期目标

TripPilot 是面向个人及小团体的国内旅行助手：通过对话说清需求，把想去的真实地点、时间和预算约束转化为可核对、可调整、可保存的行程。用户掌握地点确认、方案采用与保存权；不是通用聊天、客服或自动预订产品。

长期方向是国内目的地选择、更长行程、照片／视频发现地点，以及跨城、多住宿规划。媒体只提供线索，须核对真实POI后参与规划。**当前六城、1～7天和单住宿是版本边界，不是永久限制；未来方向不是已实现能力或一次性授权。**

## 当前入口与实现范围

| 入口／能力 | 当前事实及边界 |
| --- | --- |
| `/` 聊天入口 | chat-1已实现多轮需求意向、版本化卡片、显式确认与按账号持久对话；离线／受控流程通过，**真实模型语义仍待验** |
| 聊天地点准备 | chat-2已实现独立城市目录、主动搜索、候选预览及明确确认住宿／必去，MySQL副本持有候选与版本；离线及受控检查通过，真实模型／POI仍待验；不生成／采用／保存行程，不是loop |
| `/legacy` 旧规划工作区 | 独立保留真实地点确认、候选、规则排程、地图、天气、费用、调整预览与存档；未挂在聊天后面，不等于这些已迁入聊天 |
| `/knowledge` | 上海三个馆区的可追溯本地资料检索；**生成式问答停用**，实验、失败和评分保留 |
| `/demo` | 独立旧Mock／地图联调；Mock活动、费用和天气不参与正式计算 |

chat-1流程是主动发送→服务端绑定历史／需求版本→一次有界模型提议→程序校验和固定展示→用户确认。原话、模型提议和用户确认分层；结构及引用合法不能证明理解正确。需求变更使旧确认失效，取消／换号／晚响应不能恢复旧状态，详见[CHAT_1](CHAT_1.md)。

**chat-2离线交付**：已实现有限工具／Skill声明、一次原生工具选择、MySQL权威地点副本及独立复制迁移、全国目录和主动搜索／预览确认。通俗步骤、实际检查及缺口见[CHAT_2](CHAT_2.md)；该开发轮模型／高德业务调用0，不能把受控结果称真实质量通过。目录准备不是全国排程／天气／存档开放；chat-3须先评审接口和快照兼容，不能承诺v3任意城市。

**最新有限真实验收**：用户授权最多12次千问及有界高德，实际1次千问、0高德后暂停。首题结构合法但住宿／地点变成单字，语义及业务失败；第二题模型前遇到验收工具会话字段错误，仅离线修复。原冻结／台账不改，剩余11项及4个Chrome场景未执行，不自动续发或进入chat-3。详见[CHAT_ACCEPTANCE](CHAT_ACCEPTANCE.md)。这没有证明chat-2原生工具／真实POI链已通过。

## 保留的真实规划能力与限制

- 六城单选：上海、杭州、北京、广州、成都、西安；单城1～7天、一个住宿参考点、最多6必去／本次前三有效可选。必去原顺序、每日住宿往返、停留与午餐避让；不均分活动，空日和部分安排有效。
- 高德提供已确认POI、步行／公交参考与天气；程序排程，不由模型编造耗时或整份行程。不保证最优路线、旅行当天班次、营业、预约或门票；成都历史公交样本仍有`data_error`，不能宣称其完整公交草案已真实验收。
- 地图按正式草案当天实际访问与单段同次查询几何展示；未采用预览不影响正式地图，无几何不补直线／补查。天气按覆盖日期分别解释昼夜，未知不当晴天。
- 费用用实际时间轴逐次交通加用户估算、整数分累计；未知不是零，已知小计不是完整总价，预算不改变排程或采用资格。预览保留原方案，明确采用后才提交；保存使用冻结内容及幂等标识。
- 照片／视频选中单帧只给一个可能名称／城市或拒识，再主动高德搜索、预览并明确确认加入必去。城市别名和同名POI不证明视觉身份；限定小样本通过，不代表六城／全国可靠识别。媒体不入存档，不做批量视频多地点发现。
- 旧行程解读、自然语言单可选排除、只读日期／费用查询按需使用。7A-1原生`tool_calls`是单次选择，不是循环；其原API失败、修复离线回放与Chrome结果分别保留。

具体规则／真实证据分别见[DESTINATION_2](DESTINATION_2.md)、[DURATION_1](DURATION_1.md)、[MEDIA_1](MEDIA_1.md)、[MEDIA_2A](MEDIA_2A.md)、[MEDIA_2B](MEDIA_2B.md)、[7A-1](ITINERARY_QUERY_7A1.md)。历史次数和失败不在当前摘要重复重算。

## 实际架构与状态边界

- **前端**：Next.js 16.3.8 App Router、React 19.2.8、TypeScript、Tailwind4；Hook/ref、fetch、AbortController和单调版本／身份epoch。浏览器固定同源`/api/*`与地图代理；目标只由Next可信服务端配置决定。
- **后端**：Python≥3.13、FastAPI、Pydantic、httpx、SQLModel；API、契约、服务规则、上游适配分层。`shared/destinations.json`与`planning-limits.json`统一城市及当前／历史容量；严格前后端契约不靠全局放宽兼容。
- **AI**：百炼北京地域，行程／聊天默认既有Flash快照，照片独立`qwen3-vl-plus`。每主动轮最多一次有界请求，无自动重试；模型只提议受限结构，程序保事实边界，用户确认重要操作。后续真实验收须新授权，旧台账不返额。
- **本机新版存储**：独立MySQL承载账号、会话、邀请、对话、意向、存档和持久业务额度；地点副本新增`chat-places-storage-v1`，在随机临时MySQL演练显式复制／空扩展回退，未切现有服务或生产。SQLite仅旧兼容／迁移，无故障回退；运行不自动加表，旧库、身份锚及所有尝试状态不改写。
- **存档**：新正式快照v3支持七天；v1/v2严格保留原1～3天字段与重放含义。快照不是会话、任务恢复或长期偏好；媒体、AI、天气、地图状态与临时预览不入存档。历史打开不刷新原时间或重新核验。
- **身份与测试**：邀请注册、密码哈希、会话撤销、CSRF／Origin及服务端归属继续有效。本机免填登录只是专用普通账号自动正常登录，不是匿名后端或生产绕过；模型／高德发送在该试用环境关闭。
- **权威状态**：chat-2地点副本已有服务端权威版本／候选批次；正式草案与费用尚未接入聊天，旧行程主要仍由浏览器管理，chat-3须建立一致工作区及单一费用规则。正式草案、预览、历史与恢复输入必须分开。

存储／迁移与运行限制详见[MYSQL_REGISTRATION](MYSQL_REGISTRATION.md)、[CHAT_1](CHAT_1.md)、[RELEASE_1C](RELEASE_1C.md)、[RELEASE_1E](RELEASE_1E.md)。业务次数额度不是精确人民币上限，浏览器直连SDK／底图和入口资源保护另计。

## 当前未完成与后续依赖

chat-1真实多轮语义、生产新聊天数据备份／恢复、线上MySQL切换仍未完成。用户已报告旧版本HTTPS和登录成功，不等于代理验证了新版生产迁移；不因代码推送自动更新服务器或切库。

已有地点流程的有限工具／Skill声明，不是通用插件执行平台。有界loop、持久任务恢复、长期偏好、真实MCP和专业多Agent尚未实现。先完成多轮澄清与真实旅行工具闭环，再验证循环／恢复／记忆的收益；简单操作不强制进入loop。机票／酒店需真实数据和授权，研究比较与预订支付分阶段。

全国开放、更多天数／地点容量、批量媒体、跨城、多住宿、自动优化及完整公网运维也未完成。模型理解“轻松”等偏好不等于排程已执行；原话、已确认偏好与模型推断不能混同。

多城原话保留待澄清，错误POI归属仍拦截，真正跨城执行未实现。[城市目录](CHAT_CITY_CATALOG.md)核对官方2026-01-07表：369个大陆目录单元，港澳台／不明确归组排除；不是当前区划认证，生产条款与更新策略仍待核。
