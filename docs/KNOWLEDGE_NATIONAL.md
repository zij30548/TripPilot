# 多城市场馆与乐园知识库：可追溯检索基线

2026-10-24。用户目标是全国主要城市的场馆和乐园资料，而不是只存上海三馆区。**本轮交付第一批经过核对的目录与检索链，不宣称全国全覆盖、高答案准确率或恢复生成式问答。** 基线为`fe1435e8dc4bcfdb0544f4489b7de831792f8593`；旧知识问答阻塞、评分和所有调用台账独立保留。

## 1. 当前能用什么

`/knowledge`按城市、类型、具体场馆主动查询本地资料，显示完整主题摘要、原文短摘录、官方链接、来源日期、实际获取时间和适用性提醒。可选参观日期用于检查资料声明的时间范围，**不是联网核实今天是否开放、预约余量或可入场的证明**。没有合适文字时显示未找到；有相关文字也不自动等于回答成立。

- 首批9城、12场馆／馆区、16份资料、40个完整主题单元，其中3个游乐园。它与旅行排程仍仅六城的范围相互独立；查询重庆资料不会让重庆排程自动开放。
- 10份新增资料实际打开官方正文核对；6份上海旧资料保留原整理、获取日期及历史语义，**本轮没有重新读取它们的网页**。旧资料的留存对象哈希明确指原v1整理对象，不冒称网页原文哈希。
- 在线检索不刷新官网，不调用千问、Embedding、重排模型、高德或业务数据库。生成式`POST /knowledge/answer`继续返回停用结果。
- 新目录和片段使用独立v2；旧v1文件、请求、检索与实验输出不改。没有改写存档、MySQL表、用户数据或当前已运行的网站。

## 2. 每一步怎样做、怎样防止出错

| 环节 | 已实现与验证边界 |
| --- | --- |
| 来源与采集 | 白名单清单绑定资料ID、场馆、精确官方URL、内容版本、留存文本哈希和规范化资料哈希；实际阅读后人工整理。在线用户不能提供任意网址让服务器抓取 |
| 清洗 | `knowledge_national_pipeline.prepare`离线处理已取得的HTML／纯文本／Markdown，移除脚本、隐藏内容与导航；保留正文顺序、数字、条件、例外。严格UTF-8及容量检查，超限拒绝，不静默截断；输出始终要求人工审核，不能自动认证摘要正确 |
| 主题分块 | 每份资料按主题审核，整块最多700字摘要＋80字摘录，条件／对象／例外一起保留。不按固定字符机械切断；主题ID和资料版本可追溯，超过容量应人工重整而非自动丢尾部 |
| 嵌入准备 | 已有选装千问Embedding适配器保留；新索引提供显式离线向量附件校验，绑定语料、单元哈希、模型、维度与有限数值。**本轮未生成真实向量、未调用Embedding、未验证语义召回提升**；生产缺省只走BM25，不暗中下载模型 |
| 召回 | 中文字符／双字词BM25，先强制城市与场馆过滤；选择的地名是过滤条件，不靠地名命中任意规则。最多返回5块，不混入其他馆区；无资料、表达不足和误命中需分别评测 |
| 融合与重排准备 | 显式离线向量采用归一化余弦及RRF融合，避免把不同分数当可信度；受控重排器接收完整主题单元并返回合法完整排列，非法ID／漏项直接失败。**仅合成注入验证，不是实际重排模型或质量提升证据** |
| 输出 | 程序直接显示审核摘要、标明原文短摘录及出处，分开显示来源发布时间、获取时间和适用性；不生成预约／免票／可入园结论，不使用相似度百分比冒充可信度 |
| 评测 | 在首次评测前固定开发／验证分组、标签和门槛；分别统计证据命中、全部必要证据、无资料误命中和跨馆区。不改难题追分，不拿引用存在证明语义正确 |

本轮没有把现有EchoMind原始500字符切片、查询改写及LLM重排默认接进正式资料页。原实现与来源归属保留，但适用性、费用及错误回退边界不能靠复制框架自动成立。

## 3. 代码与严格契约

- [规范化准备工具](../backend/tools/knowledge_national_pipeline.py)：只离线文件输入，输入≤1MiB，最多4000块、单块≤20000字；源文件禁止最终软／硬链接，输出独占0600，不覆盖旧审核对象。
- [独立v2模型](../backend/core/schemas/knowledge_national.py)：拒绝未知字段、非法日期／引用／URL、重复身份和不一致馆区；资料≤500、场馆≤200、城市≤100、主题≤3000，总语料≤1MiB。它们是容量上限，不是已覆盖规模。
- [语料](../backend/knowledge/national-corpus-v2.json)和[审核清单](../backend/knowledge/national-sources-v2.json)：不依赖业务库或迁移；索引可以重复构建，不重复导入。日期未知保持null，编辑摘要不刷新获取时间。
- [检索引擎](../backend/tooling/travel/knowledge_national.py)：核心版本`cjk-bigram-bm25-national-v1`；离线受控融合／重排使用不同method，不能发布为当前生产目录。
- [API](../backend/api/knowledge.py)：`GET /knowledge/catalog-v2`不接收参数；`POST /knowledge/search-v2`只接收`city_id, venue_id, question, limit, visit_date`。问题2～160字、最多5条，请求≤4KiB／接收5秒、响应≤128KiB，目录≤1MiB；继续受匿名工作区、Origin／CSRF门禁保护。
- [前端契约](../frontend/src/lib/knowledge-national.ts)、[状态控制](../frontend/src/lib/use-national-knowledge.ts)、[资料页](../frontend/src/components/knowledge-national-search.tsx)：从服务端审核目录取得允许值，检查request echo、语料hash及来源URL／ID／馆区／版本绑定。输入变化、取消、卸载、工作区epoch变化隔离旧success/error/finally；分区切换不卸载聊天控制器。

响应是带引用的**资料结果**，不是`answer`。`historical_reference`、`outside_declared_range`、`current_applicability_unknown`等由程序规则派生；即使在来源声明日期内，也标未联网核验。查询不到不能推断免费或不需要预约。

```sh

```

```sh
.venv/bin/python -B -m tools.knowledge_national_pipeline prepare /绝对路径/公开正文.html --format html --output /绝对路径/新的私有审核对象.json
```

评测工具按下列顺序执行，输出必须是仓库外的新文件；冻结绑定题目、语料、代码与分词器，漂移必须停止，不能更新hash迁就结果。原始评测、旧1/4误命中和知识问答b05阻塞不重新评分。

```sh
.venv/bin/python -B -m tools.knowledge_national_evaluation freeze --receipt /绝对路径/新的私有目录/freeze.json
.venv/bin/python -B -m tools.knowledge_national_evaluation verify --receipt /绝对路径/新的私有目录/freeze.json

```

## 4. 质量门槛及未来生成准入

首批检索评测是同一语料下的人工标注开发／冻结验证集，不是独立人类盲测或全国泛化证明。评阅者是执行者Codex逐条对照已阅读资料；没有第二评分模型。正例要求直接相关资料和全部必要证据；`limited`只表示能提供部分依据／范围提醒，不表示用户问题已完整回答。

预先门槛：Hit@3≥90%、全部必要证据@5≥90%、无资料误命中≤10%、跨城市／馆区命中0。必须分别报告实际分子分母、MRR、每题返回、失败及适用性提示。达到检索门槛也不能自动开放问答；未达到则先保留基线和失败，另立有理由的优化版本，不能边看冻结验证题边改词典。

下一轮若获明确模型／Embedding预算，最小对照应固定同一份新问题、资料、模型快照、超时／输出上限和执行顺序：

1. 无检索模型：观察常识能答什么，以及不可追溯／过时／瞎猜。
2. 相同模型＋受控官方搜索：观察获取正文成功率、时效和来源选择，搜索摘要不能冒充正文。
3. 相同模型＋本地审核检索：比较覆盖、选材、缺失／冲突、条件保真和成本；可以另分BM25／混合／重排消融，但不可同时改变全部变量。

每个操作预先冻结并持久预记、失败及发送后取消计数；不自动重试或调用评分模型。生成内容须逐事实核对证据、适用范围和未答事项，不能只核验JSON／引用。**本轮没有这些真实调用授权和结果，当前正式问答仍停用。** 旧b05证明整块证据也会选错／漏答，不能因去掉改写就宣布解决。

## 6. 3分钟演示与面试

1. 打开知识库，明确选择城市和场馆；解释目录规模不是全国所有场馆。
2. 查询“儿童预约”或“下雨会停运吗”，展开完整主题条件、原文短摘录和来源日期；说明摘要不是官方原话，获取时间不是发布时间。
3. 改问题为未收录事项，展示无结果或旁支匹配限制；不能因为有文字就说问题解决。指定未来日期只出现适用性提醒，不制造余票。
4. 回到聊天，核对未发送内容仍保留；查询没有调整、保存行程，也没调用模型。

面试口述：**大模型能说常识，但不会因为说得流畅就有当前馆区的预约证据。我们先把官方资料、完整条件、版本和失效提示做好，再量化检索的漏召回与误命中；向量／重排是可对照的候选，不是准确率保证。生成仍未准入，不能用命中率替代事实正确率。**

可追问：

- 为什么不全网抓取？来源归属、馆区、版权和更新失败要可审核；增加数量不能牺牲可追溯性。
- 为什么不用固定字符切片？日期／儿童条件／例外拆开会让正确引用支持错误结论，完整主题单元用版本绑定。
- 为什么要场馆过滤？同名、总馆／分馆、乐园／动物园规则不能互换；过滤正确仍不能证明每条选材相关。
- 为什么尚未启用向量和生成？没有本轮付费授权、真实质量对照和事实准入；提供测试缝隙不冒充已测改善。
- 怎么定位错误？按来源缺失→清洗／分块丢条件→召回漏失→排序／选材→适用性→生成改写逐层保存同版本证据，不先追加提示。

### 9.1 把三个问题分开解决

1. **资料找不到**：例如口语“折返／另约”，需要比较真实语义召回是否比纯词法找得全，而非继续针对旧题加词。
