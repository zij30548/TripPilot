# TripPilot 产品路线图

更新：2026-10-21。**本文件是规划，不是一次性实施、部署或模型调用授权。** 当前事实见[PROJECT_CONTEXT](PROJECT_CONTEXT.md)，实际交付／停止点见[PROGRESS](PROGRESS.md)，旧计划和成绩见[历史导航](archive/README.md)。

## 当前优先级与阶段来源

当前先推进聊天式旅行助手：chat-1已实现多轮需求意向和确认／持久化，离线及受控流程通过，真实语义仍待验；chat-2未开始。旧真实规划独立保留在`/legacy`，不能把旧能力算作已接入聊天。线上MySQL切换、新聊天生产备份／恢复仍待完成；用户报告的旧版HTTPS登录与新版部署验收分开。

阶段编号、用户场景、依赖、非目标、验收及面试要求**只在[CHAT_REBUILD_PLAN](CHAT_REBUILD_PLAN.md)维护**，这里不再复制第二套规格：

- 核心顺序：多轮澄清（chat-1）→工具／Skill与真实POI（chat-2）→确定性旅行闭环（chat-3）→有界单Agent loop（chat-4）→持久恢复（chat-5）。
- 后续：经授权偏好／检索（chat-6）、真实MCP（chat-7）、有收益的专业协作（chat-8）；MCP可在能力目录稳定且有实际需要后独立安排，不是loop前提。
- chat-9是**每个拟发布版本的横向门槛**，不等所有阶段做完才上线。原一周内受控上线／演示目标保留为近期发布约束，不以新功能代替部署、安全及备份验证，也不倒推宣称已完成。
- 每阶段检查[Harness H01～H12](HARNESS_ENGINEERING.md)，评测、追踪、故障、权限、成本和恢复从首阶段贯穿；框架名或文档齐全不代表运行能力齐全。

## 长期产品主线

**全国单城规划 → 扩展天数／容量 → 照片识别并确认景点 → 短视频发现多个地点 → 跨城市、多住宿规划。** 方向顺序是依赖说明，已有部分交付不代表剩余能力自动获授权。六城、1～7天、单住宿是当前范围而非永久定位。

| 方向 | 用户价值与范围 | 依赖 | 验收目标／当前状态 |
| --- | --- | --- | --- |
| 全国单城规划 | 更多国内目的地沿用真实地点、交通、天气与保存；一次仍一城 | 统一城市身份、行政归属、供应商覆盖／权限、代理白名单和存档契约 | 分批真实样本证明不串城，未知／不支持不兜底；现有六城，非全国开放，成都完整公交历史样本仍`data_error` |
| 扩展天数与地点容量 | 更长假期，减少拆分和重复输入；天数与地点数分别设计 | 查询预算、日期／费用／地图／AI契约、兼容与性能 | 现有1～7天、6必去／本次3可选，空日有效；更多天数与容量上限待细化，不承诺均分或不限量 |
| 照片发现并确认 | 不知道名称也能从照片得到可能线索，核对后纳入旅行 | 上传安全、识别评测、城市／POI确认与取消隔离 | media-1仅单图、一个可能名称／城市或拒识→主动搜索→明确确认；限定小样本收口，不证明任意照片可靠 |
| 短视频发现多个地点 | 从多镜头提取候选并逐个核对，减少手工找点 | 已有抽帧／单帧流程、跨帧去重、来源关联、总调用与资源预算 | media-2A有限抽帧、media-2B选中单帧已限定交付；批量识别、多地点发现、排序与可选导入未实现，后续限制待细化 |
| 跨城、多住宿 | 显式换城／换住处并核对转移与缓冲 | 单城基础、新日期归属／起终点／城际数据、费用和快照设计 | 验证行程连续、必要交通与失败解释，不伪造班次；数量／来源／阶段编号待细化，不含自动购票支付 |

已有范围与证据见[DESTINATION_2](DESTINATION_2.md)、[DURATION_1](DURATION_1.md)、[MEDIA_1](MEDIA_1.md)、[MEDIA_2A](MEDIA_2A.md)、[MEDIA_2B](MEDIA_2B.md)。城市覆盖是分批而非穷尽区县；媒体小样本、同源关联和历史失败不在这里重算为总体准确率。

## 技术方向与业务准入

| 方向 | 用户价值／优先级 | 依赖与验收目标 | 非目标／停止条件 |
| --- | --- | --- | --- |
| 多轮意图与能力治理 | 先把需求问清，再搜索和明确确认真实地点；当前首要重构线 | 需求版本、严格工具输入输出／权限／副作用、服务端权威工作副本、单一费用边界 | 文字线索不冒充Place，不靠Schema宣称理解正确；chat-1真实语义未通过前不自动进入chat-2 |
| 确定性闭环与有界执行 | 先提供可用旅行工作流对照，多步任务再减操作负担 | 同工具／数据／预算比较；总轮数／Token／时长／实际尝试上限、结果反馈、无进展停止 | 简单任务单步、缺信息澄清；不无限反思，不自动采用／保存或新增额度 |
| 恢复与长期偏好 | 暂停可继续，减少下次重复输入但由用户控制 | task／step／attempt分层、时效与版本复核、未知不盲重跑；偏好授权／纠正／撤回 | 对话／最终快照不是任务恢复，推断不是长期事实；未执行的旅行约束不得宣称满足 |
| 排程优化 | 在真实约束下证明比现有固定顺序更有用 | 可靠旅行闭环后独立立项，与现规则比较硬约束、未安排、耗时和查询成本 | 不因扩城市顺手改算法，不把启发式称最优；收益不足则保留基线 |
| 检索与资料质量 | 提高相关资料查找、缺口及适用性提示 | 来源／时间／馆区隔离，固定开发验证集，Hit@k、无资料误命中与失败归因 | 知识库生成式问答继续停用；旧阻塞与评分不改，不能靠引用存在宣称回答正确 |
| MCP与专业多Agent | 真实连接复用，或独立专业任务确有收益才拆分 | 真实协议、白名单与权限；协调者＋专业子Agent＋确定性校验，共享需求版本／任务额度 | 不以MCP／多Agent数量为目标；机票／酒店先验证数据授权，研究比较与交易分阶段，不各自提交草案 |
| 工程选型与可观测 | 解决实际并发、恢复、检索、故障和成本问题 | 用现有MySQL／小状态机作对照，脱敏追踪与故障恢复指标按阶段实测 | LangGraph、Redis、向量库等另行论证，不凑栈；开发子Agent不等于产品多Agent |

实现原理和职责边界见[AGENT_EVOLUTION](AGENT_EVOLUTION.md)。尚未实现的约束、偏好、专业数据与执行能力，必须按本次真实用户问题独立定范围；不能把“模型听懂”当“程序已经做到”。

## 公开上线的横向门槛（不是等到最后才补）

| 门槛 | 当前基础 | 每次开放对应能力前需完成 |
| --- | --- | --- |
| 账号与数据隔离 | 邀请注册、服务端会话／CSRF／归属，MySQL统一私有数据；本机自动普通登录非bypass | 实际部署Cookie／来源、换号晚响应、账户生命周期、隐私与删除／保留；受控内测不等于完全公开准入 |
| 调用额度与资源 | 实际发送前持久账号／全局分类额度，有界重试、取消保守占额 | 核账／告警、任务聚合预算、入口带宽及浏览器直连地图资源；次数不是精确人民币上限 |
| 媒体管理 | 现有照片内存处理、视频私有临时处理与清理／限制 | Linux编解码兼容、上传取消／隔离、崩溃遗留清理、版权／隐私；新上传限制和容量另行细化 |
| 数据迁移、备份与恢复 | 显式独立目标迁移、旧版本严格兼容；原始媒体不持久化 | **新增聊天数据备份／恢复仍待完成**；停写、恢复隔离、会话撤销、额度不返还、RPO／RTO／保留与异地副本；线上MySQL切换未执行 |
| 部署、安全与运维 | 同源转发、Linux发布包、身份分离、systemd／Nginx／TLS手册；用户报告旧版HTTPS登录成功 | 按当前版本核对低内存资源、native／权限、HTTPS／上传、依赖告警与回退；不把本机或用户输出冒称代理完整公网验收 |

操作与剩余风险分别见[RELEASE_1C](RELEASE_1C.md)、[RELEASE_1D](RELEASE_1D.md)、[RELEASE_1E](RELEASE_1E.md)、[RELEASE_1F](RELEASE_1F.md)、[MYSQL_REGISTRATION](MYSQL_REGISTRATION.md)、[CHAT_1](CHAT_1.md)。账号数据、私密配置和旧调用台账不能为演示重置。

## 每轮实施与停止

1. 按[README](../README.md)→[PROJECT_CONTEXT](PROJECT_CONTEXT.md)→本文件→[PROGRESS](PROGRESS.md)恢复事实，再读局部指令和相关专题；历史只按需查[归档](archive/README.md)，不把过时停止点当当前授权。
2. 只选一个明确授权的闭环，冻结范围／输入／预期／版本／预算／停止条件。真实模型须新授权；历史额度、产品账号额度或未来预计次数不是维护者的新调用许可。
3. 分开实现、离线验证、历史回放、真实模型、真实上游、Chrome与服务器证据；失败、未执行、待核和取舍如实保留，不以总通过率抵消阻塞。
4. 每轮更新当前摘要及专题，解释真实原理、代码和数据流，附短口述与3～5个项目追问；只提交审查范围，不改无关工作／用户数据／五缓存，不自动继续下一阶段。
