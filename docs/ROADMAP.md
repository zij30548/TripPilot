## 主线与排序理由

当前先按新决策做本地聊天重构，线上MySQL切换暂缓；再次发布前仍须完成相应HTTPS、身份、额度、资源与恢复验证。下列保留的是长期产品能力依赖主线，不表示与聊天改造打包实施：让同一套可靠规划能力适用于国内不同城市，再扩展行程容量；之后引入照片、短视频作为发现地点的入口，最后处理跨城市及多住宿的更复杂约束：

**全国单城规划 → 扩展天数 → 照片识别并确认景点 → 短视频识别多个地点 → 跨城市、多住宿规划**

这个顺序先解决地点的城市归属和规划容量，再增加不确定的媒体输入，最后扩展交通与住宿模型。顺序是当前优先安排，不代表每个城市都已验证，也不代表识别结果可直接参与排程。多 Agent 不是任何一项的前置条件。

### 新确认的Agent路线及与产品主线的关系

最新依赖顺序为**多轮会话澄清 → 能力注册 → 确定性真实旅行闭环 → 有界执行 → 持久任务恢复 → 长期偏好与可执行旅行约束 → 专业协作**。chat-1～chat-9的场景、依赖、非目标、验收与停止点统一在[CHAT_REBUILD_PLAN](CHAT_REBUILD_PLAN.md)；MCP可在目录稳定后独立安排。架构原则与旧路线在[AGENT_EVOLUTION](AGENT_EVOLUTION.md)，参数和真实调用额度仍需逐轮冻结，不在这里复制第二套规格。

先用已有日期查询、费用核对和单可选排除预览建立有限闭环，再验证暂停继续与明确采用。简单操作仍走单步，缺信息先澄清；不强制简单查询进入多步调用，额外调用须通过效果与成本对照评估。专业协作仅在真实领域数据与独立任务收益成立时引入，机票／酒店研究比较先于预订支付；各Agent共享需求版本及额度，由统一入口提交正式结果。

城市覆盖、超过七天／地点容量、批量媒体、多住宿与排程优化方向继续保留，但不能与这一技术序列捆绑成大改造。按用户需求与验收证据另行选定单轮范围；当前照片／单帧能力也不授权批量识别。模型理解了新偏好不等于现有排程已执行对应约束。知识库生成式问答继续暂缓。

## 方向一：全国单城规划（主线优先）

- **用户价值**：不只为上海做攻略，可选择其他国内城市，仍获得可追溯的地点、路线、天气和可保存草案。
- **范围**：一次旅行仍只在一个明确城市、一个住宿参考点内；保留地点确认、只读历史与显式生成／采用规则。城市选择不能只是改界面文字，也不能根据模糊名称自动选择同名城市。
- **依赖**：统一目的地身份（城市及行政代码），核对 POI 搜索、候选检索、公交城市、天气和地图初始化中的上海绑定；同步前后端校验、取消隔离与存档兼容。服务商实际覆盖、账号权限、调用预算和支持城市范围待验证，不自动向旧 v1 存档写新字段。
- **验收目标**：使用预先选定的多个代表城市，证明搜索／住宿／必去／地图／路线／天气均不串城；不支持的服务明确降级或失败，不冒用上海数据。旧上海行程和历史存档不回归，新请求及往返住宿可核对。
- **首批实际交付**：目的地扩展第 1 阶段，仅上海／杭州／北京，仍 1～3 天／单住宿；共用城市表、上游行政归属检查、城市天气／公交／地图、v2 存档及严格 v1 兼容。三城各一组真实样本、杭州候选与调整／保存完成，具体范围与上游异常见 [报告](DESTINATION_1.md)。
- **第二批历史交付**：新增广州／成都／西安，当时沿用 v2、原预算和链路；城市接入新增表结构／重复检查及跨语言允许值一致性检查。三城 POI／步行／天气／地图、广州／西安公交及成都步行扩展流程已实测；成都公交完整草案未通过，不换样本掩盖失败。接入步骤、代码及区县来源、矩阵见 [DESTINATION_2](DESTINATION_2.md)。其当时停止点已由后续明确的 duration-1 授权取代，不表示全国完成。
- **待细化**：更多城市与分批开放标准、服务覆盖／区划维护、下一轮真实调用计划。没有验证的城市不可因代码可扩展就宣称支持；duration-1只扩展日期，media-2A也不继续加城市。

## 方向二：扩展天数（依赖单城边界梳理）

- **用户价值**：支持更长假期，不因原 1～3 天限制被迫拆成互不关联的小行程。
- **范围**：先扩展单城行程，不同时引入跨城／多住宿；天数与地点容量分别设计，不能只把校验的数字调大。继续保留空日、部分安排和可解释失败。
- **依赖**：所有请求／响应／运行时校验、UI 日期、费用逐日口径、AI 输入、存档及恢复兼容一起核对；重新评估逻辑边数量、并发、截止时间、限额、地图附件体积。天气远期无覆盖仍须显示未知，不能为了长行程补造预报。
- **验收目标**：跨月／跨年和边界天数准确；午餐、每日窗口、住宿返程不越界；真实及受控大规模样本证明请求数有界、取消清理正确、性能可接受。旧短行程和 v1 快照可读，费用不按错误天数搬运。
- **首阶段已交付 duration-1**：六城单城、1～7 天、单住宿；仍最多6必去／本次3可选，不均分、不保证每天有活动。最大描述41条逻辑边，实际仍最多29启动／58上游尝试，共享原20秒截止／并发3／0.4秒间隔；显式未核实原因。新存档v3，v1/v2严格保持原三天语义。杭州七日步行与四日公交有限实测，六城最大规模受控验证，见 [DURATION_1](DURATION_1.md)。
- **待细化**：超过七天、必去／可选容量与优化另立阶段；重新评估性能、预算及存档策略，不能把“更长”写成不限天数。全国城市仍分批推进，视频识别及跨城多住宿均未启动，照片进展见下项。

## 方向三：照片识别并确认景点（依赖目的地与上传基础）

- **用户价值**：看到一张喜欢的景点照片后，不必先知道精确名称，也能找到可确认的真实地点并加入规划。
- **范围**：照片只产生可能地点或检索线索；展示不确定性、同名／相似候选和地址。用户选择并明确确认真实 POI 后，才决定作为必去或可选输入；不凭图像输出伪坐标，不自动替换正式草案。
- **依赖**：单城目的地校验、现有 Place 确认与角色契约、媒体安全和隐私边界；识别方式／模型与费用另行选择并授权，不预定引入框架或模型供应商。图片无可识别地标、地点不在所选城市、识别与真实搜索不一致都须可拒绝。
- **验收目标**：正常地标、歧义、无地标、图中文字指令、错误城市等固定样本；识别失败不产生已确认地点，只有明确确认才影响输入。地点进入既有生成、预览采用及保存后仍可追溯，取消／旧响应不污染工作区。
- **首阶段 media-1**：仅单照片、仅必去；JPEG/PNG/静态WebP≤5MiB／2000万像素，长边缩至2048，转正并去元数据，内存处理不持久保存。独立北京qwen3-vl-plus，一次主动识别最多一次请求；城市不明／不支持／不匹配不自动加入。当前v2只一条名称／城市或空拒识，不再生成自由依据。旧完整链路／v3保存证据保留；历史保守批API清晰6/6、拒识3/4、Chrome1/2（当时英文门控阻塞）仍是该批未通过记录，不重判；见[MEDIA_1](MEDIA_1.md)。
- **当前限定收口**：六城照片线索明确中英文别名已实现，跨城仍阻止；英文门控以历史回放＋真实高德流程验证修复，不改旧评分。局部按景区／建筑身份层级及可见特征评审，不仅按裁切与否；新8图限定门槛通过，识别4、合理拒识4。结合代码版本审查，单照片线索→主动搜索→用户明确确认→必去的限定流程收口；不承诺任意照片准确定位，不把高德命中当照片匹配证明，不重算旧api02／api06或宣布普遍识别能力通过。
- **待细化／边界**：media-1限定收口保留；本轮media-2A只完成下一项的画面准备，未实现视频识别。可靠性目标、更多输入与可选角色另立范围。多图识别及公网文件管理未交付，数据库不迁移。任何新实时识别／演示／评测仍须明确范围、固定样本及新调用授权，不能复用已耗尽的12＋12＋8次历史额度。

## 方向四：短视频识别多个地点（依赖照片流程）

- **用户价值**：从一段旅行视频发现多个想去的地点，而不是手动逐帧搜索。
- **范围**：先明确支持的上传来源；不默认允许任意 URL 下载或平台爬取。提取候选与时间片段，去重并展示来源关联；逐个用户确认真实 POI、角色和加入顺序。视频片段顺序不自动等于合理游览顺序。
- **依赖**：图片确认机制、媒体存储与清理、视频解析／抽帧资源预算、多个地点的歧义处理、任务取消与状态隔离。是否需要异步任务及其实现方式待容量评估，不预先引入 Redis、队列平台或 Agent 框架。
- **验收目标**：多地点、重复镜头、无地标、字幕误导、跨城市混剪等样本；可回溯到对应片段，未知不瞎填；每个地点确认独立，失败／取消不泄漏半成品输入，不自动调用排程或覆盖已有行程。
- **media-2A已交付**：一个本地MP4/H.264≤20MiB、>0且≤30秒、长边≤1920／≤2073600像素；只主动抽帧，最多6张JPEG（≤1280长边、512KiB每张、5MiB整批）。本地预览不上传，后端FFmpeg私有临时文件、网络／外部引用禁止、单进程1任务、上传30秒／处理20秒／前端60秒，取消回收。真实Chrome和离线回归见[报告](MEDIA_2A.md)，没有任何模型、高德或视频地点识别。
- **media-2B已交付**：用户选中一帧、明确识别，复用照片v2与城市/高德确认机制，只加入编辑中必去；独立帧字节/约时间/会话，换帧及取消使旧请求失效。固定8次(4 API＋4 Chrome)限定通过，4视频5目标有复用，非总体准确率，不改原媒体评分。见[MEDIA_2B](MEDIA_2B.md)。
- **待细化**：批量多地点、跨帧证据与去重、加入排序、可选导入、后续真实模型预算和阶段编号。单帧已接入不授权自动遍历6帧、追加调用或无限长/全平台链接。公开文件隔离与运维另需准入。

## 方向五：跨城市、多住宿规划（主线后置）

- **用户价值**：一份旅行覆盖多个城市、换酒店与不同住宿日程，不再假设每天回同一个点。
- **范围**：显式城市段、住宿及日期归属、每天起终点、城际转移与缓冲；是否提供真实城际服务需单独定范围。不等于增加自动购票、支付或保证赶上班次。
- **依赖**：全国单城与长行程稳定；新的住宿／转移约束、费用口径、排程与路线查询预算、地图分区、快照版本及旧记录兼容。媒体发现只作为输入来源，不能替代跨城交通真实性验证。
- **验收目标**：换城、换住宿、过夜与不可达等固定案例；必要移动与住宿连续，失败不丢必去、不伪造车次；旧单城流程可复用，存档／继续规划保留所有输入和原查询时间。
- **待细化**：城市／住宿数量、城际交通方式与数据来源、停留及入住规则、费用边界、契约迁移和阶段编号。

## 公开上线的横向门槛（不是等到最后才补）

本地单用户迭代可先继续，但**公开多用户开放前必须完成**与开放功能相匹配的安全和运维工作。当前本地 CORS、SecretStr、接口大小上限、SQLite 幂等和验收台账都不能代替这些能力。

## 每轮准入、交付与停止

1. 先读 [README](../README.md)、[PROJECT_CONTEXT](PROJECT_CONTEXT.md)、本文件、[PROGRESS](PROGRESS.md) 和局部指令，核对 HEAD、远端、工作区与已有缓存。
2. 将一个方向细化为单轮范围：用户路径、契约、容量、兼容、风险、验收样本及停止条件。具体参数待细化不是临时拍定的授权。
