# 直接使用：匿名浏览器工作区

更新：2026-10-23。基线 `9597ac36bcd455d88c5674344be22bd53f463fb4`。用户要求移除登录、注册、邀请码和账号菜单，本轮落实当前产品入口和后端协议，不删除原数据。以前的账号和邀请码报告保留历史含义。

## 使用方式

直接打开本机 `http://127.0.0.1:3110/` 即可进入对话、知识库、Agent评测三页。无需填写账号、密码或邀请码，也不再使用8810登录辅助入口。工作区连接失败时显示明确原因及手动重连入口，不自动重发模型或业务请求。

浏览器用私有Cookie保存工作区访问凭据；聊天、明确保存的偏好、存档和任务回执仍在MySQL，按工作区隔离。同一浏览器刷新可以继续访问，另一个浏览器或无痕窗口建立独立工作区。完整清除站点Cookie后无法找回旧工作区；这里没有账号登录、跨设备同步或找回功能。

原账号和历史记录不会被删除、重写或自动转给匿名工作区。旧账号的Cookie不能读取当前产品，知道其他记录的ID也不获得访问权限。未保存的正式草案、费用和程序追加消息仍是浏览器临时状态，刷新会丢失，与前一阶段相同。

## 实现与数据边界

1. 前端 `WorkspaceBoundary` 在进入时读取 `GET /workspace/session`。已有有效工作区直接继续；否则取得短期预CSRF与独立HttpOnly随机seed，再由前端自动 `POST /workspace/session`，正文严格为 `{}`。
2. POST核对可信Origin、CSRF、私有seed、128字节正文与10秒上传界限。公开CSRF不会派生身份凭据；seed只存在HttpOnly Cookie中，未知字段、客户端owner、跨站请求均拒绝。
3. 后端从私有seed按用途派生稳定owner、会话和不可预测token，原子创建或恢复。同一seed并发或创建响应丢失后重试不会创建多个owner。会话30天，恢复seed365天；过期后持有seed可恢复同一工作区，清除全部Cookie则无法恢复。
4. 原MySQL的owner与会话表继续使用，不新增表、不运行DDL或切换数据库。内部owner有精确的 `workspace_`＋ID及 `!anonymous-workspace-v1` 标记，不能通过密码登录。迁移／备份校验仅对该完整组合明确兼容，其余旧账号仍严格要求原Argon2id，不泛化忽略密码字段。
5. `WorkspaceMiddleware` 在读请求体、处理媒体或创建上游依赖前校验工作区、CSRF和owner，绑定原持久业务额度。当前正式应用不挂载旧账号路由，直接 `/auth/*` 返回404；浏览器同源转发也移除旧四条身份路径。
6. 前端保留epoch、AbortController、流式响应、操作版本及确认校验。服务器过期后即使恢复同一session_id也先递增epoch、取消旧请求；更换工作区、晚成功／错误／finally及A→B→A不能把旧结果写回。

内部运输层暂保留 `auth-session.ts` 名称及 `authenticated/user` 响应形状，供原领域控制器兼容；它不再含登录、注册或退出请求函数。登录注册界面和密码组件已删除。未挂载的旧后端身份模块、迁移CLI和专用历史测试保留，避免删掉原数据兼容及失败证据；不作为当前产品功能。

## 限额及配置

- 匿名创建有持久全局30次／5分钟和单seed6次／5分钟限制，原子取额，返回明确等待时间；不是内存重启后复原。
- 原服务分类额度、全局硬额度、路线预算、媒体容量和任务循环上限保留；旧模型台账及消费不会清零。清Cookie可建立新owner，因此单工作区额度不能冒称原账号抗重建额度，公开部署仍需入口防滥用与费用运维验证。
- 本轮真实模型、高德和其他外部业务API调用0。登录移除不等于新的维护者调用授权，也不改变当前试用服务的天气／地图代理／视觉／媒体0额度。
- 复用现有 `AUTH_COOKIE_SECURE` 和 `AUTH_ALLOWED_ORIGINS` 配置名控制Cookie与可信来源；仅本地HTTP设false，HTTPS应为true。新工作区固定30天会话不使用旧 `AUTH_SESSION_SECONDS`；没有关闭全站安全检查的开关。
- 显式MySQL为前提，失败不回退旧SQLite；没有改真实 `.env`、密钥、生产数据库或云服务器。原SQLite、身份锚及五缓存受保护。

## 取舍与面试解释

这次取消的是凭据和邀请流程，数据仍需要归属。浏览器得到随机私有访问凭据，服务端确定owner，避免把所有人合并到公共账号。创建恢复有原子事务与幂等，原业务确认、额度和版本保护继续生效。代价是清Cookie或换设备无法找回，匿名owner可重建，因此费用保护必须保留持久全局上限，不能宣称具备账号身份强度。

可核对的追问：为什么不能共享固定owner；初次响应丢失如何避免重复建区；为何同session恢复还要失效旧回调；如何拒绝旧账号Cookie；清Cookie后额度有哪些限制。实现和测试分别回答这些问题，不宣称完成公开部署或完整Agent恢复。

停止在无登录入口、工作区隔离和已列验证；不增加账号找回、新模型调用、云端发布或其他Agent功能。
