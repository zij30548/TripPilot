# 旅行候选小型验收方案：先固定计划，再授权发送

2026-10-23，开发基线 `main / c042cce3200531aa4453963dbc209af724f42593`。

**本轮只准备验收，真实模型、高德和其他外部业务API均0次。** 用户的“开始”承接零调用方案准备，不是新的付费授权。没有修改候选、提示、Schema、模型、数据库、环境文件、现有服务或网站；知识生成问答仍停用。

## 1. 要验证什么

验证现在的**协调者 direct-tools → 原生工具反馈 → 后端严格操作提议 → 浏览器原控制器 → 实际业务状态**，不再迁移框架或增加Agent。四个旅行角色已定义，但当前正式opt-in每轮没有前置融合分类，未传明确意图时由协调者选工具；自动专业并行关闭。本组不能证明四Agent协作、三路融合、向量检索、Judge或任意旅行问题都正确。

受控测试已经证明部分程序接线和安全边界；真实模型是否理解原话、选对工具、尊重否定和多轮修正，必须另验。反过来，HTTP200、模型输出流畅、服务端waiting回执也不证明浏览器完成了操作。

**本方案先隔离变量：未来使用真实千问＋明确标注的合成旅行输入／受控高德transport。** 不对真实高德、天气、公交、地图底图重新验收，计划高德物理发送为0。合成地点不得写成已从高德核实的真实POI。这可以先定位理解与执行问题；之后若要补真实地点联调，须独立固定输入及有界查询计划，不在本批偷偷增加调用。

## 2. 固定问题、前提和顺序

机器清单：[echomind-travel-acceptance-plan-v1.json](../backend/evaluations/echomind-travel-acceptance-plan-v1.json)。原第3步的16题[离线清单](../backend/evaluations/echomind-travel-v1.json)完全保留，不重算成绩；本组是有意缩小的已知题验收，不是独立盲测。

### 前提分开，不能拿旧工作区凑成功

- `empty`：独立空会话，未确认需求、地点、草案和费用均为空。
- `requirements`：另一空会话，M02→M03使用本次真实历史及响应；不注入预写助手答案。确认前一直是需求草稿；没有地点搜索和排程。
- `formal`：另一独立会话，上海2026-11-01～02、2人、预算3000、步行；沿用[既有受控工具](../backend/tools/echomind_travel_controlled.py)的“受控住宿甲／受控景点甲／受控公园甲”。先通过原接口／控制器正常准备：明确确认需求、合成地点搜索／预览／确认、准备规划、候选及生成。首日有一个必去及一个可选，第二天空日；09:00～18:00、停留各60分钟、午餐关闭、各方向参考360秒、住宿往返。候选仅该公园，无替补。费用为必去门票`0`、可选门票空白、首日餐饮`100`、次日餐饮／住宿／其他空白。程序应算交通参考0、已填估算100、小计100；缺项不当零。

这些是**待实例化的受控前提规格**，不是本轮已经新建的数据库或成功草案。未来实际准备须记录每次本地提交、请求及Mock上游次数，验明首日／空日和版本后才可发送；前提不符先离线检查，不修改返回凑前提。不得启动受控工具的模型固定回答来冒充本组真实模型。既有`scenario_tools`仅是Mock资料，正式模型选择不依赖按题匹配。

## 3. 预算是建议，不是授权

- 当前授权：**模型0，高德0**，本轮实际亦0。
- 建议未来独立授权最多**21次模型物理发送**：7个任务×原硬上限3。常见工具选择＋反馈预计14次；若先读取输入再提议可达3次／任务。14只是路径估算，不是上限或已发生次数。
- 本地7次提交和前提准备不调用模型；每次都要观察是否真的0，不能仅相信设计。自动Embedding、融合分类、重排、Judge、翻译、合成和其他AI不开放，不另加连通性探测。
- 所有角色共享每task3模型／4工具／45秒，不因换角色重置。实际角色参数为`max_tokens=900`、`temperature=0.1`、非思考、非流式、`tool_choice=auto`、`parallel_tool_calls=false`；通用单次最大2048／任务输出预约6144是外围上限，不能将旧验收器固定2048误当本候选实际参数。以[profile](../backend/echomind_core/travel_engine.py)及[provider](../backend/echomind_core/provider.py)为准。
- 两次预览是预定不同操作，不按第一次成败挑选执行；若前置链失败，依赖操作记未执行，不能手工注入成功结果补齐。语义／结构失败保留，独立组只在无执行安全异常时继续。
- 版本、计数、权限、鉴权／额度／限流、网络／超时／取消或未经确认写入发生异常时暂停；普通选错工具不能修补成成功。失败、已发送取消和发送不明均保留占额；到上限立即停，无自动重试、补抽、换模型或下一轮调参。

## 4. 什么已冻结，什么还不能称为就绪

本轮冻结：固定问题、顺序、前提规格、评审／停止规则、调用建议、当前业务源码／前端控制器／Skill／Schema／共享注册及锁文件哈希。独立[离线工具](../backend/tools/echomind_travel_acceptance_plan.py)没有sender、不会创建可消费台账，授权始终0。快照独占创建、0600，拒绝覆盖和符号链接；verify重枚举文件集合，新增／删除／内容变化均拒绝。

**完整live payload尚未冻结，`live_ready=false`。** 真实owner／会话／operation、当前revision／确认、浏览器workspace版本、最近实际历史和显示标签必须从未来隔离环境捕获，不是现在编一份固定JSON就有效。首发payload应在发送前冻结；后续工具call ID及反馈payload由实际上一响应决定，要记录各次实际hash及来源绑定，不能提前伪造或用模板hash冒充。评审、题号、前提准备说明和标准答案不得进入模型输入；离线`business_input`只投影用户原话，也不是完整provider请求。

另有明确执行门缺口：旧[echo_acceptance_runtime](../backend/tools/echo_acceptance_runtime.py)硬编码旧授权、3/1/3/1操作和续验白名单；当前[AdmittedTravelTurn](../backend/echomind_core/integration.py)要求精确`MeteredAsyncClient`类型，旧计数子类不能直接套用。**后续必须先针对当前发送边界准备并受控验证新的计数适配，不能改旧授权、新建目录借额、删除类型检查或启动付费探测。** 此项工具适配不是本轮完成的能力，实施／授权执行协议须关联本冻结件，旧freeze不覆盖；生产候选源码变动则必须暂停并说明新版本。

来源／计数：旧Echo迁移5/8已封存，旧chat9/12仍暂停，其他全部历史台账保持。仓库外本轮保护收据只读记录16份既有ledger的原始SHA256；未新建调用账本或复用剩余次数。

## 5. 评分、证据和准入

人工逐项判定，通过／失败／待核／未执行分别计数，不使用评分模型：

1. **结构和引用**：真实native tool_calls、白名单工具、合法参数及本轮绑定；正文不替代工具。
2. **理解与覆盖**：原话中的缺项、否定、城市修正、完整日期、指定目标是否正确，没有漏重要要求。
3. **事实／费用**：最终程序输出与同份正式草案／`calculateScheduleCosts`逐项一致；未知、零、非法及空日不改义。
4. **确认／状态**：原生响应→后端规范提议→浏览器确认／执行三个层次分别取证；waiting不是业务成功。预览不采用，取消不改正式，采用使用所见结果并拒绝旧token。
5. **成本／体验**：每次发送前预记及物理尝试数、工具数、耗时、请求模型、可取得的上游标识／用量；缺失记未知。文字冗余与不必要多次工具另记，不以次数当准确人民币。

证据需包含实际请求／payload哈希、合法结构化工具输出、程序结果、前后状态摘要和必要截图；仅合成输入可保留业务片段，不记录Cookie、CSRF、认证头、密钥、原始私人提示或网络日志。本批未来Chrome只在隔离实例，400px／键盘／取消和状态保护优先通过本地操作或受控测试，不为截图追加模型调用。地点／地图外站请求必须被禁止；不保存任何存档到用户库。

无依据事实、跨工作区、未经确认修改、错误版本采用、重复发送、计数故障仍发送均属阻塞，不能用总通过率抵消。7模型项及7本地项都应有效通过且无关键待核，才可说**本组已知题、合成业务前提下的限定链路通过**。任何缺项都如实记录，不宣布六城可靠、专业多Agent、公开上线或整个迁移验收完成；真实高德/公交/天气/视觉和Linux生产另列未验。

### 面试怎么讲

“我把模型是否理解、工具是否选对、程序有没有真正完成分开验收。精确本地命令不算模型成绩，一次聊天里的选择和反馈也分开计费计数。先固定问题、状态和失败标准，用合成业务隔离模型因素，再单独验真实来源；未知结果不重跑，任何未经确认的正式变更都是阻塞。”

- 为什么不是四场景四调用？场景可含多次用户提交，每task又可有2～3次物理模型发送；本地确认单列。
- 为什么不把最终文字流畅算成功？模型最后正文不提供事实，必须核对工具、提议和原控制器实际状态。
- 为什么现在不能完整预造payload？实际历史和工具反馈尚未产生；只能冻结生成规则，未来记录真实绑定和每次hash。
- 为什么不用旧验收器直接跑？授权／操作范围和精确客户端准入不同，复用会产生错误额度或绕过风险。
- 这次能证明什么？只证明准备清单和离线保护机制，真实质量尚未评分，未授权就不调用。
