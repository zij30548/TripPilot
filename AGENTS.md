## Rules

- 2026-10-20 MySQL/invitation registration increment: read docs/MYSQL_REGISTRATION.md before identity/storage/usage/deployment work. Explicit TRIPPILOT_MYSQL_URL selects accounts, sessions, admission buckets, invitations, archives AND durable business attempts in MySQL; no SQLite fallback on failure, runtime DDL, quota reset or automatic migration. Preserve stable IDs, ownership, snapshot v1/v2/v3, all attempt states and the original external identity anchor. SQLite remains a legacy-compatible backend; registration there fails explicitly until migration. POST /auth/register is an explicitly public, CSRF+Origin+bounded-input+durable-rate-gated admission endpoint, not a business bypass. Do not treat old release-1D's three-public-endpoint list as an instruction to remove this checked endpoint.
- MySQL migration/restore must use empty isolated targets and private new receipts. DDL is not rollback-safe; final imported DML and private ready marker commit together. Never retry uncertain COMMIT, overwrite source/target, restore old allowances or resurrect sessions automatically. Logical restore tools are rehearsal-only, revoke sessions and do not authorize a production switch. Local real-MySQL tests are not Ubuntu/production migration evidence. User-reported HTTPS/login deployment status must be distinguished from independent agent verification.

- release-1E adds persistent account/global business-attempt quotas in an independent SQLite ledger, not exact RMB billing or new model authorization. Never delete/reinitialize a missing ledger/identity anchor to replenish allowance. Runtime fails closed; browser-direct SDK/tiles and ingress resource protection remain separate. See docs/RELEASE_1E.md and latest PROGRESS; knowledge Q&A remains disabled.

- release-1D adds invitation-only authentication and per-account saved-trip isolation for controlled testing, not public-launch clearance. Read docs/RELEASE_1D.md before identity/storage/deployment work. Every backend business/external/media endpoint requires a server session; unsafe calls also require CSRF and trusted Origin. Only GET /health, GET /auth/session, POST /auth/login and non-executing CORS preflight are public. Knowledge Q&A stays disabled after authentication. Never add a runtime auth bypass for tests.
- New private storage defaults to backend/data/trippilot-private.sqlite3 (trusted absolute-path override). Never point it at the old backend/data/saved-trips.sqlite3. Migrate only a consistent copy; legacy ownerless rows remain quarantined, never assigned to the first account. Snapshot v1/v2/v3 semantics remain unchanged. Auth/ownership schema version is separate from snapshot version. Rehearse migration/rollback with temporary databases; no in-place restore or user-data reassignment without explicit authorization.

Session Cookie/password/CSRF values are not evidence or log content. Login throttling is not an upstream business quota. Current release stop is release-1D; earlier media stop statements describe their own product branch, not permission to start new work.
