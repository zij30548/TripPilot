# TripPilot

聊天式国内旅行助手：先把旅行想法聊清楚，再通过真实地点、规则与用户确认形成可核对的方案。面向希望自主规划的个人及小团体；模型辅助理解，不编造交通、价格、天气或预约事实。

## 当前版本：EchoMind 旅行架构适配版

本轮按用户提供的 EchoMind 架构重组旅行后端：角色路由、原生工具反馈循环、Skills、MySQL任务检查点与明确偏好、技术监控和评测。聊天按需复用已有旅行卡片及规划工作区。迁移范围、来源贡献、检查和待验事项见 [ECHOMIND_MIGRATION](docs/ECHOMIND_MIGRATION.md)；下列9/12属于独立旧聊天验收记录，不是新架构成绩。当前云端和原试用服务不会随代码修改自动切换。

更新：2026-10-22。新增独立8次授权实际使用千问 **5/8**、高德 **4次物理发送**。首版api01结构失败保留；严格`index=0`兼容补修后，原计划中尚未发送的澄清、Chrome需求整理与主动搜索3项通过，并完成一份真实上海步行／费用／保存回看链。不是4题全部通过或六城质量认证，详见[真实复验](docs/ECHOMIND_MIGRATION.md#73-固定真实复验与显式同预算续验)。旧chat-1／2累计9/12后暂停、剩3未执行，见[独立旧报告](docs/CHAT_ACCEPTANCE.md)。首页不会自动生成或采用行程。

旧单次意向接口及其有界输出补修保留供兼容和对照；新聊天使用独立原生工具反馈路径，没有放宽旧AI契约。历史截断诊断见[旧补修说明](docs/CHAT_ACCEPTANCE.md#11-需求整理有界输出补修2026-10-21离线通过真实效果未验)，不能把新受控测试填入旧成绩。

| 入口 | 当前能力／边界 |
| --- | --- |
| `/` | 聊天、按需需求／地点／行程卡；有限原生工具loop、执行记录和明确同意的偏好。生成、采用和保存仍主动操作 |
| `/legacy` | 旧链接兼容；同一确定性规划／费用实现，已由聊天内行程卡复用，不再作为主导航 |

| `/demo` | 独立旧Mock／地图联调示例，不是正式旅行数据 |

当前旅行工具范围为上海、杭州、北京、广州、成都、西安**单城、1～7天、单住宿，最多6必去／本次3可选**。这是当前范围，不是长期限制；空日有效，不保证最优或每天有活动。成都完整公交样本的历史`data_error`限制保留，不能据此宣称六城所有路线可用。

## 使用与本地测试

- 聊天：主动表达／澄清→核对意向→“准备真实地点”中确认城市、主动搜索、预览地址、明确确认住宿／必去→“行程工具”核对并准备独立副本→主动生成→核对费用、预览、明确采用和保存。面板编辑不会回写聊天意向；普通聊天查询不清除相同输入的本地草案，实际输入变化会失效。
- **新版本机试用**：先打开一次`http://127.0.0.1:8810/`，本机工具通过正常CSRF／密码登录测试账号后跳转`http://127.0.0.1:3110/`。独立测试MySQL、正常产品传输和持久计数，未切换旧库或线上；不是关闭鉴权。仍沿用严格限额，天气／地图代理／视觉及媒体处理暂关闭，勿存重要资料；详见[试用边界](docs/ECHOMIND_MIGRATION.md#75-独立本机手工试用入口)。旧`http://trippilot-test.localhost:3104/`保留旧schema及关闭真实发送的环境，不是本次新版。
- 历史只读，继续规划在独立页面创建副本、主动重新生成后另存。当前草案和费用仍是本地控制器状态，刷新前需要明确保存；持久任务回执不等于完整规划断点恢复。

### 从源码启动（须先准备独立私有数据库）

环境：Python>=3.13、uv、Node>=20.9、npm；依赖以`backend/uv.lock`和`frontend/package-lock.json`为准。使用现有服务前先核对端口与工作目录，不覆盖用户配置或数据。

```sh
# 终端一：仅本地HTTP；先按开发手册准备MySQL／聊天扩展、账号和额度。
cd backend
uv sync --frozen
AUTH_COOKIE_SECURE=false .venv/bin/python -B -m uvicorn main:app --host 127.0.0.1 --port 8000 --no-access-log
```

```sh
# 终端二
cd frontend
npm ci
TRIPPILOT_BACKEND_ORIGIN=http://127.0.0.1:8000 npm run dev -- --webpack
```

打开`http://localhost:3000`。这组是通用开发端口，不是3104旧试用服务。运行命令不负责初始化／迁移数据；新聊天还须显式准备`assistant-storage-v1`，缺少扩展会明确失败，不能在旧库启动时自动建表，见[迁移步骤](docs/ECHOMIND_MIGRATION.md#6-显式复制迁移与运行边界)。

完整配置、生产构建、测试命令及媒体依赖见[本地开发手册](docs/LOCAL_DEVELOPMENT.md)。前后端配置分离：后端`backend/.env`、前端`frontend/.env.local`，只参考示例，不提交真实值；仅浏览器地图公开Key可用`NEXT_PUBLIC_`，服务端Key和安全码不可进入浏览器。

## 实际架构与AI分工

| 层 | 已有实现 |
| --- | --- |
| 界面 | Next.js 16.3.8 App Router、React19.2.8、TypeScript、Tailwind4，Hook/ref与原生fetch |
| 同源访问 | 固定`/api/*`／`/_AMapService`；Next服务端可信origin与明确白名单，非任意URL代理 |
| 后端 | Python/FastAPI、Pydantic、httpx、SQLModel／SQLAlchemy；按EchoMind的api／agents／core／tooling／memory／monitor／evaluation／skills组织，严格契约和有界上游 |
| 状态／存储 | MySQL承载账号、会话、邀请、存档、额度、聊天；本轮显式增加assistant任务检查点和用户同意偏好。旧SQLite仅兼容，MySQL故障不回退，启动不执行DDL |
| 模型 | 千问北京地域；旅行角色与有界原生tools／tool_calls反馈，固定上游、持久额度和程序校验；新链路有有限真实样本，首版失败独立保留。旧AI能力与知识问答停用边界保留 |
| 事实与计算 | 高德真实地点／路线／天气，确定性规则排程与整数分费用；模型不能提供伪造POI、耗时或总价 |

行程快照仍为v3，v1/v2保持原1～3天严格语义；聊天及地点副本分别使用`chat-storage-v1`／`chat-places-storage-v1`显式扩展，不把最终行程当任务检查点。媒体不入存档；照片和视频选中单帧只提供一个可能地点或拒识，须主动搜索真实POI并明确确认，限定样本不代表全国可靠识别。

参考来源为用户提供EchoMind版本`ef847eb5b719ef98be9d5673f3429e62cd88109e`。迁移采用其执行与分层设计，并改造成旅行工具、千问协议、MySQL归属／CAS与安全确认；没有直接复制Anthropic、Redis、Chroma或Docker全套。角色分流不代表并行专业多Agent，技术测试不等于真实模型业务质量通过。源码目录、数据复制及贡献说明见[迁移专题](docs/ECHOMIND_MIGRATION.md)。

## 当前限制与发布状态

- 新运行时真实样本有限，首版api01失败不改判，修复版未重跑该题；旧9/12也独立保留。词法角色路由、有限loop及用户同意偏好有实现，不是并行专业多Agent、自动任务恢复、无限记忆或通用插件平台。
- 地点、会话、任务与偏好由MySQL管理；聊天内正式草案／费用仍由既有前端控制器处理，不将React状态直接当服务端检查点。日期／费用查询工具目前指引对应程序面板，不声称服务端持有未同步的正式草案。
- 用户报告旧版HTTPS／登录可用；当前新版本未同步云端，生产MySQL切换及新聊天备份／恢复仍未准入。不能把本机验证写成公网部署完成。
- 聊天城市目录含369个大陆目录单元，仅供地点准备／归属参考，生产条款及更新策略待核；不等于全国排程、天气或v3存档开放。跨城原话保留待澄清，不偷偷执行一城。交通仍为查询当时参考，营业／预约、预算优化、跨城／多住宿和批量视频多地点发现未实现。
- 所有旧模型台账与失败保留，历史额度不是新授权；演示或复验的真实模型调用须另行明确授权。
