# TripPilot

聊天式国内旅行助手：先把旅行想法聊清楚，再通过真实地点、规则与用户确认形成可核对的方案。面向希望自主规划的个人及小团体；模型辅助理解，不编造交通、价格、天气或预约事实。

## 当前版本：聊天重构中

更新：2026-10-21。**chat-1代码、离线测试和受控浏览器流程已交付，真实模型语义验收尚未完成。** 当前首页只整理需求，不是在聊天中自动生成完整行程。

| 入口 | 当前能力／边界 |
| --- | --- |
| `/` | 自己的对话、多轮需求意向卡、显式确认；持久会话，不是Agent loop、真实POI或任务恢复 |
| `/legacy` | 独立保留旧版真实规划、地图、天气、费用、调整预览、存档和历史副本；尚未迁入聊天 |
| `/knowledge` | 上海三馆区的可追溯本地资料检索；生成式问答仍停用 |
| `/demo` | 独立旧Mock／地图联调示例，不是正式旅行数据 |

当前旅行工具范围为上海、杭州、北京、广州、成都、西安**单城、1～7天、单住宿，最多6必去／本次3可选**。这是当前范围，不是长期限制；空日有效，不保证最优或每天有活动。成都完整公交样本的历史`data_error`限制保留，不能据此宣称六城所有路线可用。

## 使用与本地测试

- 聊天：正常会话→主动表达／补充需求→核对意向卡→明确确认。地点名称仍只是线索，chat-2尚未开始。
- 本机已准备的试用入口：`http://trippilot-test.localhost:3104/`。独立工具替测试账号完成普通登录，刷新保留会话；不是删除注册登录或关闭鉴权。该试用环境真实模型／高德发送关闭，不能当真实聊天质量验收。退出／过期及准备条件见[本地入口说明](docs/CHAT_1.md#2026-10-21本机测试暂时免填登录不删除功能)。
- 旧规划：`/legacy`确认真实住宿／必去→主动候选或生成→核对安排／费用→预览后取消或采用→明确保存。历史只读，继续规划创建独立副本、主动重新生成后另存。

### 从源码启动（须先准备独立私有数据库）

环境：Python>=3.13、uv、Node>=20.9、npm；依赖以`backend/uv.lock`和`frontend/package-lock.json`为准。使用现有服务前先核对端口与工作目录，不覆盖用户配置或数据。

```sh
# 终端一：仅本地HTTP；先按开发手册准备MySQL／聊天扩展、账号和额度。
cd backend
uv sync --frozen
AUTH_COOKIE_SECURE=false .venv/bin/python -B -m uvicorn main:app --host 127.0.0.1 --port 8000 --no-access-log
```

```sh
# 终端二
cd frontend
npm ci
TRIPPILOT_BACKEND_ORIGIN=http://127.0.0.1:8000 npm run dev -- --webpack
```

打开`http://localhost:3000`。这组是通用开发端口，不是上述已运行的3104专用试用服务。运行命令不负责初始化／迁移数据，缺少聊天扩展时会明确失败。

完整配置、生产构建、测试命令及媒体依赖见[本地开发手册](docs/LOCAL_DEVELOPMENT.md)。前后端配置分离：后端`backend/.env`、前端`frontend/.env.local`，只参考示例，不提交真实值；仅浏览器地图公开Key可用`NEXT_PUBLIC_`，服务端Key和安全码不可进入浏览器。

## 实际架构与AI分工

| 层 | 已有实现 |
| --- | --- |
| 界面 | Next.js 16.3.8 App Router、React19.2.8、TypeScript、Tailwind4，Hook/ref与原生fetch |
| 同源访问 | 固定`/api/*`／`/_AMapService`；Next服务端可信origin与明确白名单，非任意URL代理 |
| 后端 | Python/FastAPI、Pydantic、httpx、SQLModel／SQLAlchemy；严格契约和有界上游 |
| 状态／存储 | 当前本机新版使用MySQL：账号、会话、邀请、存档、额度和聊天；旧SQLite仅兼容，MySQL故障不回退。显式迁移，不启动DDL |
| 模型 | 千问北京地域；chat-1一次主动轮提出结构化意向，程序校验并展示。旧行程解读／受限调整／原生只读tool_calls独立保留 |
| 事实与计算 | 高德真实地点／路线／天气，确定性规则排程与整数分费用；模型不能提供伪造POI、耗时或总价 |

行程快照仍为v3，v1/v2保持原1～3天严格语义；聊天使用独立`chat-storage-v1`扩展，不把最终行程当任务检查点。媒体不入存档；照片和视频选中单帧只提供一个可能地点或拒识，须主动搜索真实POI并明确确认，限定样本不代表全国可靠识别。

## 当前限制与发布状态

- 真实多轮语义待验；尚无统一工具／Skill目录、有界loop、完整任务恢复、长期偏好或产品多Agent。
- 旧规划主要仍由前端维护状态；新聊天接工具前需服务端权威工作副本与单一费用规则，不直接搬React状态。
- 用户报告旧版HTTPS／登录可用；当前新版本未同步云端，生产MySQL切换及新聊天备份／恢复仍未准入。不能把本机验证写成公网部署完成。
- 交通是查询当时参考，不保证旅行时运营；营业／预约、预算优化、全国城市、跨城／多住宿和批量视频多地点发现尚未实现。细分失败与未验收范围见专题报告。
- 所有旧模型台账与失败保留，历史额度不是新授权；演示或复验的真实模型调用须另行明确授权。
