# TripPilot

聊天式国内旅行助手：先把旅行想法聊清楚，再通过真实地点、规则与用户确认形成可核对的方案。面向希望自主规划的个人及小团体；模型辅助理解，不编造交通、价格、天气或预约事实。

当前产品已移除登录、注册、邀请码和账号菜单。打开页面自动建立独立的浏览器工作区，直接使用三页；聊天、偏好与存档按该工作区隔离。保留同一浏览器Cookie可以继续访问，清除Cookie／更换浏览器不能找回旧工作区。历史账号数据保留，不自动交给新工作区。机制和限制见[匿名工作区](docs/ANONYMOUS_WORKSPACE.md)。

## 使用与本地测试

- 聊天：直接打开→表达想法→回复／澄清或提出具体操作→明确确认→程序执行并回报。地点使用编号预览后再确认；真实地点及需求齐备后主动准备、生成、核对费用、预览／采用和保存。资料查询和执行核对在另外两页，往返保留未发送文字。
- **新版本机试用**：直接打开`http://127.0.0.1:3110/`，无需账号、密码或邀请码。复用独立测试MySQL及持久计数，未切换旧库或线上；天气／地图代理／视觉及媒体处理仍受原额度限制，勿存重要资料。旧8810一次性登录工具不再是使用步骤；旧`http://trippilot-test.localhost:3104/`是历史服务，不是本次新版。
- 历史只读，可通过聊天操作恢复输入，旧独立副本入口也保留；必须主动重新生成后另存。当前草案、费用及程序追加的聊天结果仍在本地，刷新前需要明确保存；持久任务回执不等于浏览器动作完成或完整规划断点恢复。

### 从源码启动（须先准备独立私有数据库）

环境：Python>=3.13、uv、Node>=20.9、npm；依赖以`backend/uv.lock`和`frontend/package-lock.json`为准。使用现有服务前先核对端口与工作目录，不覆盖用户配置或数据。

```sh
# 终端一：仅本地HTTP；先按开发手册准备MySQL／聊天扩展及额度。
cd backend
uv sync --frozen
AUTH_COOKIE_SECURE=false .venv/bin/python -B -m uvicorn main:app --host 127.0.0.1 --port 8000 --no-access-log
```

```sh
# 终端二
cd frontend
npm ci
TRIPPILOT_BACKEND_ORIGIN=http://127.0.0.1:8000 npm run dev -- --webpack
```

打开`http://localhost:3000`。这组是通用开发端口，不是3104旧试用服务。运行命令不负责初始化／迁移数据；新聊天还须显式准备`assistant-storage-v1`，缺少扩展会明确失败，不能在旧库启动时自动建表，见[迁移步骤](docs/ECHOMIND_MIGRATION.md#6-显式复制迁移与运行边界)。

完整配置、生产构建、测试命令及媒体依赖见[本地开发手册](docs/LOCAL_DEVELOPMENT.md)。前后端配置分离：后端`backend/.env`、前端`frontend/.env.local`，只参考示例，不提交真实值；仅浏览器地图公开Key可用`NEXT_PUBLIC_`，服务端Key和安全码不可进入浏览器。

## 实际架构与AI分工

| 层 | 已有实现 |
| --- | --- |
| 界面 | Next.js 16.3.8 App Router、React19.2.8、TypeScript、Tailwind4，Hook/ref与原生fetch |
| 同源访问 | 固定`/api/*`／`/_AMapService`；Next服务端可信origin与明确白名单，非任意URL代理 |
| 后端 | Python/FastAPI、Pydantic、httpx、SQLModel／SQLAlchemy；按EchoMind的api／agents／core／tooling／memory／monitor／evaluation／skills组织，严格契约和有界上游 |
| 状态／存储 | MySQL承载匿名工作区、会话、存档、额度、聊天及已有显式assistant任务／同意偏好扩展；沿用原表，不删除旧账号／邀请数据。旧SQLite仅历史兼容，新工作区故障不回退，启动不执行DDL |
| 模型 | 千问北京地域；旅行角色与有界原生tools／tool_calls反馈，固定上游、持久额度和程序校验；此前迁移有有限真实样本，当前dialogue-v2动作选择仍待真实验收。旧AI能力与知识问答停用边界保留 |
| 事实与计算 | 高德真实地点／路线／天气，确定性规则排程与整数分费用；模型不能提供伪造POI、耗时或总价 |

行程快照仍为v3，v1/v2保持原1～3天严格语义；聊天及地点副本分别使用`chat-storage-v1`／`chat-places-storage-v1`显式扩展，不把最终行程当任务检查点。媒体不入存档；照片和视频选中单帧只提供一个可能地点或拒识，须主动搜索真实POI并明确确认，限定样本不代表全国可靠识别。

参考来源为用户提供EchoMind版本`ef847eb5b719ef98be9d5673f3429e62cd88109e`。迁移采用其执行与分层设计，并改造成旅行工具、千问协议、MySQL归属／CAS与安全确认；没有直接复制Anthropic、Redis、Chroma或Docker全套。角色分流不代表并行专业多Agent，技术测试不等于真实模型业务质量通过。源码目录、数据复制及贡献说明见[迁移专题](docs/ECHOMIND_MIGRATION.md)。

## 当前限制与发布状态

- 新运行时真实样本有限，首版api01失败不改判，修复版未重跑该题；旧9/12也独立保留。词法角色路由、有限loop及用户同意偏好有实现，不是并行专业多Agent、自动任务恢复、无限记忆或通用插件平台。
- 地点、会话、任务与偏好由MySQL管理；聊天内正式草案／费用由既有前端控制器处理，日期与费用查询读取当前有效本地状态、以确定性文字展示。动作提议回执不证明浏览器已执行；本地程序消息、费用和草案未变成服务端持久恢复。
- 用户报告旧版HTTPS／登录可用；当前新版本未同步云端，生产MySQL切换及新聊天备份／恢复仍未准入。不能把本机验证写成公网部署完成。
- 聊天城市目录含369个大陆目录单元，仅供地点准备／归属参考，生产条款及更新策略待核；不等于全国排程、天气或v3存档开放。跨城原话保留待澄清，不偷偷执行一城。交通仍为查询当时参考，营业／预约、预算优化、跨城／多住宿和批量视频多地点发现未实现。
- 所有旧模型台账与失败保留，历史额度不是新授权；演示或复验的真实模型调用须另行明确授权。
