# TripPilot

把想去的地点和旅行约束，变成可核对、可调整、可保存的行程草案。TripPilot 面向希望自主安排国内旅行、但不想在地点、交通、时间和费用之间反复手工核对的个人及小团体用户；AI 辅助理解与查询，真实数据和确定性程序负责事实、排程与计算。

**当前面向邀请账号的受控内测：上海、杭州、北京、广州、成都、西安六选一，单城、1～7 天、一个住宿参考点。它们是当前版本范围，不是永久产品定位。** 不代表全国全部可用；更多城市、进一步扩容、视频批量多地点发现、跨城及多住宿仍是未来方向，见 [路线图](docs/ROADMAP.md)。

release-1D 增加管理员创建邀请账号、登录／退出／会话撤销及服务端存档归属隔离；无公开注册或账号后台。退出、失效或换号清空本页未保存工作。旧无归属本机库不改写、不对账号公开；使用独立新库，迁移只能在副本执行。**这不是全部公开上线门槛已通过**，操作、访问矩阵、回退和验收范围见 [RELEASE_1D](docs/RELEASE_1D.md)。

## 当前能做什么

- 确认日期、人数、预算、每日窗口，搜索并明确确认真实住宿参考点与必去地点。住宿参考点不是酒店预订；搜索预览不等于确认。
- 正式新建或编辑表单可从一张照片获得一个可能名称／城市，或无候选的不确定／拒识结果，再主动搜索高德、预览地址并明确确认加入必去。仅选文件不上传；不自动切城、加入或排程。照片城市仅按六城明确别名匹配，不做模糊翻译／未知回退；跨城、混写或城市不明仍阻止照片关联搜索。只有固定小样本通过，不作为可靠自动识别承诺。
- 独立“短视频画面准备”：一个本地MP4/H.264≤20MiB、≤30秒、长边≤1920且≤2073600像素；主动上传后临时解码，最多6张JPEG带约时间。选中一帧后可明确识别，再复用照片的城市检查、真实POI搜索与确认；不自动识别、加入或规划，可能漏掉短暂画面。
- 主动按兴趣获取所选城市的候选地点，按 POI ID 去重，保留必去，手动排除／恢复可选地点。搜索保留上游城市／区县字段，归属缺失、矛盾或跨城明确失败，不凭名字补全。
- 主动生成真实交通估时草案：整份选择步行或公交／地铁参考方案；必去按输入顺序优先安排，必去完整后每日尾部最多补充一个可选地点。当前最多 6 个必去、本次前 3 个有效可选；每天从同一住宿出发并返回。
- 设置停留时间（默认 60 分钟，可改 15～480 整数分钟）和午餐窗口；展示等待、返程、部分安排与未安排原因，不用虚构活动填满日期。
- 查看正式草案的每日地点地图、访问编号、时间轴与 Marker 双向定位；主动查看一个实际交通段的同次查询几何，不额外查路线、不拼接全天路线。
- 独立查询所选城市逐日天气，按真实覆盖日期显示昼夜预报。用户标注本次游览方式，再主动检查同日天气依据；不自动重排、不用上海天气兜底。
- 核对参考交通费、用户填写的门票／餐饮／住宿／其他估算与预算差额。未知不当零，非法金额不沿用旧结果；预算不参与排程或采用资格。
- 对一个已安排的可选地点生成排除预览，比较新旧时间、地点及费用；取消保留原草案，明确采用后才更新正式状态。自然语言调整也仅支持这一受限动作，不是任意改行程。
- 保存正式草案到 SQLite，查看只读历史；从历史在新标签页创建独立副本，主动重新生成后另存新记录，不覆盖原存档。
- 按需使用行程事实解读、自然语言调整和只读行程查询。7A-1 用原生 `tools/tool_calls` 选择“某日安排／全程费用／澄清”，程序读取当前绑定快照，不修改行程。
- 在独立 `/knowledge` 页面检索已收录的上海三馆区官方资料，显示整理摘要、短摘录、链接、来源时间和适用提示。**知识库生成式问答继续停用**；相关资料不等于问题已获回答或今天适用。

## 核心使用流程

1. 打开首页 `/`，使用管理员提供的邀请账号登录，明确选择六个开放城市之一，搜索确认该城市住宿参考点与需求，点击“确认需求，开始规划”。这一步只进入工作区，不调用旧 Mock 计划，也不自动生成草案。
2. 有必去地点可直接设置停留、午餐与交通方式；没有必去时，先主动准备并保留至少一个可选候选。
3. 点击“生成行程草案”，核对实际安排及未安排原因，再按需打开地图、查询天气、填写费用。AI、天气和预算填齐均不是生成或保存的前置条件。
4. 需要调整时查看预览，比较后明确采用或取消；普通候选排除／规则修改会使草案失效，需要主动重新生成。
5. 保存当前有效正式草案。首页和工作区的历史入口可回看；“基于此行程继续规划”打开独立副本，原记录不变。未保存工作刷新会丢失，没有自动保存。

编辑副本切城需要重新确认地点；取消不改变原工作，确认后清空旧城候选、草案、天气、地图、AI、预览和全部费用估算。旧上海 v1 存档仍只读可查，但继续规划需重新搜索确认住宿及必去，不能把缺失归属当成已核验；旧可选不自动恢复为有效输入。

正式入口是 `/`，历史副本路径是 `/plan/from/[id]`（由历史详情打开），资料入口是 `/knowledge`。`/demo` 单独保留旧 Mock 行程与地图联调；其费用、天气和活动不能混入正式草案。历史列表／详情是页面内入口，不存在独立 `/history` 页面。

| 部分 | 当前实现与职责 |
| --- | --- |
| 前端 | Next.js **16.3.3** App Router、React **19.2.8**、TypeScript、Tailwind CSS **4**；React Hook/ref 管理会话与请求版本，原生 fetch，无额外全局状态库 |
| 接口寻址 | 浏览器固定同源路径；Next 内置 rewrite 转发至服务端 `TRIPPILOT_BACKEND_ORIGIN`，固定资源白名单、不重试、不解析媒体正文；构建和启动目标必须一致 |
| 后端 | Python **>=3.13**、FastAPI、Pydantic/pydantic-settings、httpx；`api` 接口、`schemas` 契约、`integrations` 上游适配、`services` 规则与检索 |
| 真实数据 | 高德 Web Service 提供 POI、步行、公交参考与天气；JS API 2.0 提供底图，官方 loader + 受限后端安全代理 |
| 规则与计算 | 后端纯规则排程消费规范化交通分钟；前端整数分费用计算、天气关联与确定性结果展示。没有 OR-Tools、自动优化或模型生成整份行程 |
| 千问 | 百炼北京地域，当前默认 Flash 快照 `qwen3.7-flash-2026-07-15`；解释选事实、调整选受限意图、查询选白名单工具。每次主动操作最多一次模型请求，无自动重试、二次总结、自主循环或多 Agent |
| 照片线索 | 独立 `qwen3-vl-plus` 配置，Pillow **12.3.0** 内存解码、转正、去元数据与缩小；v2只给单个名称／城市或空候选，固定提示未经核实；地点 ID、坐标及归属仍来自高德确认链路；不保存照片 |

| 存档 | SQLModel + 本机 SQLite，新正式快照 `saved-trip-v3` 支持七天与城市／归属；旧 v1/v2 保持各自 1～3 天严格读取与重放。原表与 JSON 存储、请求级 Session、幂等冲突检查不变 |
| 资料检索 | 仓库内版本化官方语料、中文词法 BM25；本地检索，不自动抓网、不调用模型或 Embedding |
| 验证 | Python unittest/httpx 受控测试；前端 Vitest/Testing Library、lint、类型检查；真实 Chrome 证据与自动测试分开记录。浏览器工具不是产品运行时 Agent |

## 本地启动与配置

以下是操作说明，历史生产构建验收曾使用这些命令。已有服务时先核对并复用，不重复占用端口、不误停其他进程；media-2A核对PID/目录后重启了生产前后端，未修改环境文件。

前置环境：Node.js **>=20.9.0**（本地 Next 包要求）、npm、Python **>=3.13**、uv。依赖以 [frontend/package-lock.json](frontend/package-lock.json) 和 [backend/uv.lock](backend/uv.lock) 为准，不重新初始化项目或无故升级。

视频功能额外依赖 FFmpeg/ffprobe，本轮在 macOS 经权限流程执行 `HOMEBREW_NO_AUTO_UPDATE=1 HOMEBREW_NO_INSTALL_CLEANUP=1 brew install ffmpeg`，实际版本9.0.1、路径`/opt/homebrew/bin/{ffmpeg,ffprobe}`。服务端只选固定可信安装目录，需支持fd协议等本轮参数；其他平台／版本须验证，缺依赖只让视频接口明确不可用。详情和来源见[MEDIA_2A](docs/MEDIA_2A.md)。不增加模型或环境配置。

### 1. 配置文件

在本机创建 `backend/.env`、`frontend/.env.local`，分别参考 [后端示例](backend/.env.example)、[前端示例](frontend/.env.example)。**已有文件只补缺项，不覆盖；不要把真实值发到聊天或提交到 Git。**

| 文件 | 变量 | 用途 |
| --- | --- | --- |
| `backend/.env` | `AMAP_WEB_KEY` | 服务端 POI、步行／公交、天气 |
| `backend/.env` | `AMAP_JS_KEY` | 与前端 JS Key 一致，供受限代理校验 |
| `backend/.env` | `AMAP_JS_SECURITY_CODE` | 仅服务端使用的 JS 安全密钥，绝不能放入 `NEXT_PUBLIC_` |
| `frontend/.env.local` | `NEXT_PUBLIC_AMAP_JS_KEY` | 浏览器专用 JS Key；公开配置，不是服务端 Web Key |
| `frontend/.env.local` 或进程环境 | `TRIPPILOT_BACKEND_ORIGIN` | **仅Next服务端**的后端 HTTP(S) origin；开发省略时才默认本机8000，生产构建和启动均须明确配置且一致 |
| `backend/.env` | `AMAP_ALLOWED_PAGE_ORIGINS` | SDK页面来源精确白名单（JSON列表）；默认本地3000两个来源，部署时配置实际HTTPS站点，不等于CORS或任意上游许可 |
| `backend/.env` | `QWEN_API_KEY`、`QWEN_BASE_URL`、`QWEN_MODEL` | 可选 AI 配置；密钥仅后端，当前模型默认快照见上表 |
| `backend/.env` | `QWEN_VISION_MODEL` | 独立照片模型，当前仅允许 `qwen3-vl-plus`；复用上述北京地址与服务端密钥，不改三项行程AI默认模型 |
| `backend/.env` 或进程环境 | `AUTH_COOKIE_SECURE`、`AUTH_ALLOWED_ORIGINS`、`AUTH_SESSION_SECONDS` | 默认安全 Cookie、精确可信页面 origin、固定会话期限；仅本地 HTTP 显式设置 Secure=false |
| `backend/.env` 或进程环境 | `TRIPPILOT_DATABASE_PATH` | 可选绝对路径；默认新私有库 `backend/data/trippilot-private.sqlite3`，不能指向原无归属库 |

`QWEN_BASE_URL` 只能使用当前服务端白名单内的北京官方 HTTPS 地址和 `/compatible-mode/v1` 路径；具体配置边界见 [QWEN_SETUP](docs/QWEN_SETUP.md)。该文档是 6A-1 配置与历史验收记录，其中的旧调用额度不是新授权，原解释接口的 JSON 输出说明也不能替代 7A-1 原生工具协议。不要修改配置来换模型或绕过历史额度。

后端从固定 `backend/.env` 读取，进程环境优先。密钥缺失不阻止 API 启动，但对应真实查询会给出未配置错误；地图未配置会显示提示，不伪造地图。前端公开变量在构建时注入，改动后需重启开发服务或重建生产包。

不再配置浏览器后端地址。旧 `NEXT_PUBLIC_AMAP_SERVICE_HOST` 已不读取，已有本机环境文件可自行移除该废弃项；它不能覆盖新的同源代理。地图 `serviceHost` 从当前页面 origin 生成，安全码仍仅在后端。`TRIPPILOT_BACKEND_ORIGIN` 不使用 `NEXT_PUBLIC_`，不允许凭证、子路径、query或fragment，也不接受请求参数选择目标。

### 2. 后端（从仓库根目录，在终端一）

```sh

.venv/bin/python -B -m uvicorn main:app --host 127.0.0.1 --port 8000 --no-access-log
```

账号名为小写 ASCII 3～48 字（字母、数字、`_.-`），密码交互输入两次、12～128 字，不放进命令行、环境或文档。撤销全部会话：`.venv/bin/python -B -m tools.account_admin revoke YOUR_INVITED_USERNAME`；禁用账号：将 `revoke` 换为 `disable`。无需每次启动都创建账号。

本地健康端点 `http://127.0.0.1:8000/health` 公开；其余业务和 API 文档均需有效会话。Cookie不按端口隔离，但跨端口写请求仍必须符合 Origin／CSRF；日常通过前端同源接口使用。`-B` 避免写 Python 字节码缓存。不要为启动或连通性检查额外请求付费模型。

### 3. 前端（从仓库根目录，在终端二）

```sh
cd frontend
npm ci
npm run dev -- --webpack
```

打开 `http://localhost:3000` 或 `http://127.0.0.1:3000`。浏览器使用页面同源 `/api/*`；开发服务端默认转发到本机8000。FastAPI原有CORS不放宽，生产也不应改成 `*`；同源转发不依赖浏览器跨域访问后端。

复现已采用的生产构建方式（从仓库根目录执行，先停止同端口开发服务）：

```sh
cd frontend
TRIPPILOT_BACKEND_ORIGIN=http://127.0.0.1:8000 npm run build -- --webpack
TRIPPILOT_BACKEND_ORIGIN=http://127.0.0.1:8000 npm run start -- --hostname 127.0.0.1 --port 3000
```

这里的 loopback 是**Next服务器自己的后端**，不是访问者电脑。更换后端目标必须重新构建，并以相同值启动；缺失、非法或与构建清单不一致均明确失败，不静默使用旧地址。此方案需要 `next start` 的Node服务，不支持纯静态导出。配置路径、超时、上传、入口网关及仍缺的上线工作见[部署适配说明](docs/RELEASE_1C.md#配置与部署步骤)。

仓库也有 `npm run dev` / `npm run build`，但历史代理执行环境遇到 Turbopack 端口权限限制，验收沿用 Webpack；不能把此限制写成全平台 Next.js 故障。现有 `next/font/google` 在干净构建时需要字体网络访问；最近构建结果见 PROGRESS；media-2A已运行Webpack生产构建。

## 已知限制

- 当前仅上海／杭州／北京／广州／成都／西安单城、1～7 天、同一住宿；仍最多 6 必去和本次前 3 可选，不自动均分或保证每天有活动。城市开放不保证任意地点间都有有效公交方案，成都历史样本仍有 data_error。必去原顺序、可选尾部补充不是最优路线或完整可行性搜索。旅行节奏尚未参与排程，“不想去”的文字未自动语义过滤；兴趣只用于固定检索映射。
- 七天最多描述 41 条逻辑路线，但实际启动仍最多 29 条／58 次有界上游尝试；必去优先，两个阶段共享 20 秒搜索截止、并发 3、0.4 秒启动间隔。未启动的边明确记为预算／截止未核实，不补造时间；清理可能增加返回耗时。几何、响应及 2 MiB 存档限制不扩张。
- 公交使用查询当时的参考方案，没有核验旅行日期／具体出发时刻的班次、等车或换乘；无失败后步行兜底。没有营业、门票、预约或安全适宜性保证。
- 天气覆盖、新鲜度和地点资料各有边界；无覆盖不补邻日，摘要不是官方原文，词法命中不等于回答正确。知识库 `/knowledge/answer` 固定返回 `503 / knowledge_answer_disabled`，不调用模型；研究候选和失败评测保留，未上线。
- 费用是实际时间轴交通参考加用户估算，不是实时报价或预算优化。部分安排只核算已安排部分，不能表示整个需求已满足预算。
- 未保存工作不持久化。存档是旧快照，不代表重新核验；不含 AI、天气、调整预览、完整候选历史或新增步行绘图附件；已有公交规范化数据按原契约保存。
- 单段地图缺失／超限时不补造直线，保存和时间轴仍可用。当前不提供全天路线拼接、导航或正式草案自动调序。
- 历史真实验证与受控测试须分开：7A-1 原 8 次 API 失败、修复版离线重放 8/8、修复版续验 Chrome 4/4，不能合称 12/12 成功。实体手机、广泛语言能力、真实故障等未验收分支见阶段报告。
- 照片仅JPEG/PNG/静态WebP，一次一张≤5MiB、≤2000万像素，发送前长边≤2048；无图片URL下载、相册或持久存储；视频抽帧是另一入口，不会自动调用照片功能。单进程同时处理1张不是跨实例限流。当前视觉JSON Object输出仍须服务端严格校验，合法结构也不保证识别正确；原12/12与保守版新增12/12均已用尽，不自动重试或追加。
- 视频仅短MP4/H.264、确定性中点采样，不保证找全场景；服务端会临时落盘再清理，不是完全不落盘。单进程1任务／上传30秒／处理20秒／前端60秒，不是跨实例配额或完整OS沙箱；进程被强杀／主机崩溃后的遗留清理与公网隔离须另行设计。
- 已有最小邀请登录、可撤销会话及存档归属隔离，但没有公开注册、找回密码、完整公网上传管理、部署运维或全局业务调用限额；不能直接当作公网多用户产品发布。持久登录限流不是高德／模型账号配额。历史安全告警与测试依赖弃用提示需独立复核，不以本轮替代完整安全审计。
- Next代理空闲超时配置75秒、请求克隆缓冲21MiB，原照片5MiB／35秒和视频20MiB／60秒前端限制不变；代理空闲超时不替代业务总截止。缓冲不是全局限流或流式零拷贝；外层网关必须支持足够大小／时限、取消传播及非缓冲上传，不能直接套用较小的托管函数上限。本轮仅验证本机不同端口的生产转发，不代表公网HTTPS、入口防护或真实业务已重新验收。
